## The ruling

On a PoC box the install, start and update paths stop for five things only, kept as refusals (D-1091): (1) the
bundle's or update's signature or hashes do not hold; (2) the machine physically cannot run it (disk, memory, card);
(3) a PoC box would load real patient data or become PRODUCTION; (4) the step needs root and does not have it; (5) a
secret would be read from, or written to, a place others can read (the integrator, 7095256773). Every other
stop, on a PoC box, warns, is written to one list that `doctor` shows, and the install goes on. On a PRODUCTION box
nothing changes now.

## a. What a PoC box is, at each point of the path

One rule, the same in the shell (`tb_poc_box`, in the STOP-OR-WARN block of `deploy/install.sh`) and in Python
(`tools.trialbox.stops.poc_box`); a test runs both over the same table of boxes. A PoC box is one whose every
speaking source says DEV, TEST or VALIDATION. The sources, read only from what a caller cannot forge into a looser
state on a PRODUCTION box:

- `TB_ENV` in `deploy/.env`, the box's record (written by the installer, mode 0600), read as compose reads it: a
  leading `export`, blanks before the name or around `=`, a comment after an unquoted value; the last line wins
  (`tools/rehearsal_real.py` `env_file` is the model; review H-1 of #1396). A file that is there but cannot be read (a
  dangling link, a folder), or a value that is none of the four, is a box that cannot be told: PRODUCTION.
- An installed box (its `settings.yaml` or `updates/installed.json` in `deploy/`) with no `TB_ENV`: PRODUCTION (D-127).
- The rehearsal mark `deploy/site/rehearsal.json`, on a box that records no environment yet: VALIDATION.
- This run's command line: `--environment` and `--rehearsal` (VALIDATION). `--environment` is upper-cased only, as
  the first check (ENV-EARLY) reads it, so a value that check refuses is no PoC box either (review L-2). The script
  copies them into
  `TB_STOP_ARG_ENV` and `TB_STOP_REHEARSAL` itself, after reading its arguments; a caller's variable of that name is
  overwritten, never read. The stricter of the record and the command line wins: `--environment VALIDATION` never
  loosens a box that records PRODUCTION.
- Nothing speaking (a fresh box, no environment given): PRODUCTION, the D-127 default.

At each stage of the path this reads:

| Stage | What speaks | So |
| --- | --- | --- |
| a fresh install, before `deploy/.env` exists | the command line only (`--environment`, `--rehearsal`); the mark if a rehearsal left it | no environment given: PRODUCTION (every stop stops) |
| the run from the signed tree | the same files and the same arguments (`exec` with the first run's arguments) | the same answer as the first run |
| after the settings step | `deploy/.env` as the wizard and the rehearsal step wrote it, and the command line | the stricter of the two |
| at boot, the start path | not converted by this card (`deploy/settings_guard.sh`, `tools/trialbox/launch.py`) | unchanged |

TEST is a PoC box (the integrator's answer to H94-02, 7096436960). No environment variable of the caller is read:
`TB_ENV`, `TB_REHEARSAL`, `TB_HOST_PROFILE`, `TB_STOP_*` or `ANCHOR_OK` exported by a caller change nothing
(`ANCHOR_OK` is set by the script before the anchor block: review H-2).
`test_on_production_the_same_forced_points_stop_with_master_s_words` plants them on every PRODUCTION run and compares
the bytes with a run without them.

The H-89 rules stand: an explicit `TB_ENV=PRODUCTION` is PRODUCTION; a rehearsal-marked box never becomes
PRODUCTION (kept refusal 3, at each place the script could make it so); a box whose state cannot be told behaves as
PRODUCTION.

## b. Stops the next lines depend on

For each such point the card chose one of three:

- **It is one of the five**, named in its comment. The bundle that is not there, its sidecar hash, the signature,
  the load (each payload's hash as it lands), the signed release that lacks its image, host tree or installer, an
  image with no digest pin or not on the box, model weights whose hashes do not hold, and the pin of the pair (it
  hashes the weights against the release's, D-358; D-887 ruled it a real fault on a rehearsal box): (1). No
  signature or hash check warns. Pre-start's first check, its rehearsal guard (a box with a rehearsal sign never
  starts as PRODUCTION, `tools/rehearsal_real.py` `start_refusal`): (3), run on its own before pre-start on a PoC box
  so pre-start's warning never covers it (review M-2). A FAIL line of the host check about a secret's mode
  (`deploy/.env`, a key, a token): (5), it stays a FAIL on a PoC box and the install ends 1 (review M-1).
- **The step it guards is skipped**, and the list says what: the host baseline that would cut the SSH session (its
  apply step is skipped), the install lock with no `flock` (no lock), an anchor folder that cannot be mounted or that
  the console's user cannot read (not mounted), an override that is missing or others could change (not used), TLS settings that do not pass
  (TLS not added: the console stays on 127.0.0.1), three GPU profiles no install serves (a card with MIG on, a
  whole B200, an Arm host with another card: the box goes on as `--mode stub`), the bench-only options of a rehearsal with real servers (a plain rehearsal), a tier that may not be
  installed (no tier), site keys that cannot be made (not sealed).
- **It stays a stop, marked `H-94 depends`** (H94-03). The integrator's ruling (7096436960: one is kept only if
  it protects one of the five on the input that reaches it, otherwise it warns, one line each) is applied to these
  15 in part 2, a later pull request, at the lane H lead's word; here they stay stops: a command line not understood
  (an unknown option, `--mode`, `--gpu`, `--tier-check` without `--tier`), Docker or its compose plugin missing or not
  running, the host's python3 missing a module the host steps import, another installer holding the lock, no
  settings and no terminal for the questions, the operator's own "no" before the start, the database that does not
  start, the stack that does not become healthy, and the finish check (`finish_check`: FINISH-EARLY, ANCHOR-GATE,
  FINISH-GATE). On a PoC box the finish check refuses only an anchor folder the console may not be given (a system
  folder, the install's own); root's nightly signer mounts each anchor folder read-write
  (`tools/trialbox/audit_heads.py`), so a warned refusal would let it write into, say, `/etc`.

## c. The one list

`deploy/site/poc-stops.jsonl`, with the site's own files, so it survives the run from the signed tree, an update and
a second install. One JSON object per line: `key` (`install.sh/<name of the point>`), `what` (the stop's own words),
`skipped` (what was not done because of it), `at` (UTC), `by` (the script). Both helpers append to it, only when the
file is not a link and is owned by root or the installing user; a secret's value (`..._PASSWORD=`, `_TOKEN=`,
`_SECRET=`, `_KEY=`, `PASSPHRASE=`) is written `<hidden>` and a path under `uploads/` is never written. A list that
cannot be written is a line on stderr, never a stop. The shell writer makes it 0640 directly (under `umask 027`),
as the Python writer does (review L-4). The list is the last install's own: install.sh empties it when an install
starts, before its first `stop_or_warn` (not in the run from the signed tree, which is the same install, nor in
`--check`, `--tier-check` or `--ctgov-check`), so a point fixed before the next install is not shown again (review
L-3).

`trialbox doctor --env-file deploy/.env` shows each point (the newest line per key) as one line:

    WARN  poc_stop  install.sh/<key> (<when>): <what>; skipped: <what was not done>. Action: fix what it names before this box serves a site, then run the step again

A list made by hand, a line that is not an entry, or a list that cannot be read is a WARN line too, never a FAIL.
On PRODUCTION nothing is written: the helper stops first.
