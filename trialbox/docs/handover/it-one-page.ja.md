# TrialBox：病院情報システム部門向けの1ページ（納入業者が準備したボックス）

**Reader:** hospital IT（病院情報システム部門）。ボックスは納入業者が準備して届き、設定はボックスのオーナーがコンソールから行います。情報システム部門にお願いするのは以下の6点です。ポートの一覧は[ネットワークシート](network-sheet.ja.md)にあります。

ボックス自身の確認項目の一覧（`libs/tb_common/preflight.py`）から `tools/it_one_page.py` が作成しています（10K-18, D-1378）。手で編集しないでください。ボックスは各項目を自分で確認し（`doctor --preflight`、RUNBOOK §1）、済むまで以下の文とともに赤または黄色で表示します。

## 情報システム部門へのお願い

### ネットワーク

- **ボックスの名前と証明書**：病院のIT担当者に、ボックスの名前を院内DNSに登録し（ボックスのアドレスを指すように）、病院の証明書を使う場合はその名前を含む証明書を発行するよう依頼してください。
- **時計とタイムサーバー**：病院のIT担当者に、ボックスから院内のタイムサーバー（NTP）に届くようにしてもらい、そのアドレスをボックスの納入業者に伝えてください。時計が同期するまで待ってください。
- **メール中継サーバー**：病院のIT担当者に、メール中継サーバーの名前とポート番号を確認し、ボックスからのメールを受け付けるよう設定してもらってください。

### 保存先

- **バックアップ先の共有フォルダー**：ボックスの外にバックアップ先（2台目のディスクまたは病院の共有フォルダー）を選び、病院のIT担当者にボックスからの書き込み権限を設定してもらってください。
- **監査記録の保管先**：病院のIT担当者に、ボックスの外にある追記専用（WORM、一度書いたら変更できない）共有フォルダーを用意してもらってください。ボックスはファイルを追加できますが、ボックスの管理者（root）を含め、書いた後のファイルを変更・削除できない設定にします。

### 病院データ

- **病院データの受け取り**：病院のIT担当者に、ボックスが読み込むフォルダーにデータの出力を置き、ボックスから読めるようにしてもらってください。見つかったファイルの数がこの行に表示されます。

## 納入業者が準備したもの

これらもボックスが確認します。情報システム部門へのお願いはありません。ここが赤のときは納入業者が対応します。

- ディスクの空き容量
- 鍵の保護（TPM、ディスク解錠はTangも使用）
- GPUと性能区分の記録

## アドレスとファイアウォールの設定

- ボックスの固定アドレスを1つ（DHCPの予約で構いません）と、院内DNSの名前を1つ。オーナーはこれを `TB_TLS_HOSTNAME` に書き、職員はブラウザで `https://<その名前>` を開きます。
- **受信：** 診察室のPCのネットワークからボックスへの TCP 443。それ以外にボックスへ届くものはありません。
- **送信：** インターネットは不要です。更新は署名付きの媒体で届き、試験の一覧も更新に含まれます。インストール時に病院が ClinicalTrials.gov のオンライン利用を選んだ場合のみ：`clinicaltrials.gov` への TCP 443。
- **院内：** 時刻サーバーへの UDP 123。バックアップと監査記録の共有フォルダーへの NFS 2049 または SMB 445。メール中継サーバーを使う場合はそのポート。

ボックスについての質問は、まずオーナーへ。オーナーがボックスの納入業者に連絡します（RUNBOOK §7）。
