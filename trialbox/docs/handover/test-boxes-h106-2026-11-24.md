## 1. The design

**The mode is an install option, recorded in the box's own settings.** `deploy/install.sh BUNDLE --test-box NAME
--port-offset N [--gpus 2,3] [--gpu-mem-gb 48]` writes `deploy/site/test-box.env` (the record) before the bundle
loads, then its lines into `deploy/.env`. A later run of the installer without the option, an update and every
`trialbox` command read the record; no caller's variable makes a box a test box, names its project or moves its
secrets. The ruling names variables for the root folder and the card set (`TB_BOX_ROOT`, the card list variable);
the design rule (no caller's variable decides a guard or where a secret goes) wins: the folder is the folder the
installer runs from, the cards are an option. The helper is `tools/trialbox/testbox.py` (the host's python3).

| Per box | How |
| --- | --- |
| root folder | the folder its `deploy/install.sh` runs from; `tools/testboxes.sh up` puts box NAME at `/opt/trialbox-test/NAME` |
| compose project | `tbt-<name>-<6 hex of the folder's real path>`: two folders never share one, whatever their names; exported by the installer for its whole run, and in `deploy/.env` (`COMPOSE_PROJECT_NAME`) for every later command |
| networks, volumes | compose's own naming from the project (H-75's `${COMPOSE_PROJECT_NAME}-net` and the others; `<project>_<volume>`): the site keys' `tb-secrets` is the box's own |
| port offset | N from 1 to 49; each published port is its base plus 10 x N (console 8090, TLS proxy 8443 instead of 443 through the box's own `deploy/site/test-box.yml`, monitoring 9090); offset 0 is the ordinary box's |
| card set | `deploy/site/test-box.yml` (with the TLS port): every service of the box's compose files that reserves a card gets the box's cards, by index |
| memory cap a card | each model server's `--gpu-memory-utilization` in `deploy/.env`, scaled so it asks its card for what it would ask of a card of the cap (the profile's own utilisations x cap / the card's memory) |

**What enforces the cap:** the serving engine's utilisation setting, nothing else. The container engine has no
per-container card memory limit. The scaling is tested with a stand-in for the card's memory figure; the real cap is
shown only on the bench host's cards (not run).

**A test box says what it is:** the console's banner on every page ("TEST TEST BOX NAME: one of several boxes on this
host; synthetic data only"), `trialbox doctor` (a standing WARN on the `rehearsal` line, with its project, console port, cards and
cap; FAIL when the record and `deploy/.env` disagree or the box is not TEST or DEV), and the install's last lines (the
same words, and how to reach its commands). The doctor's line is its `rehearsal` check's (a test box is never a
rehearsal box), so the doctor's set of checks is master's. There is no `trialbox status` command on master; the doctor is the
operator's status.

**PRODUCTION is unchanged, and never weakened by the mode.** A PRODUCTION install (the box read as
`tools/trialbox/stops.py poc_box` and the shell's `tb_poc_box` read it) refuses `--test-box` before anything, and
refuses a host where a test box runs (read from the container engine: each project with a `tb-secrets` volume; its
folder from its containers' labels; a test box by its project's form and its folder's record). A test box refuses a
host with a PRODUCTION box, or with a box whose folder cannot be found (it cannot be told), and a folder installed as
anything else is never made a test box. The refusal of a second ordinary box is master's, word for word (H106-02).

## 2. The guards, and the harm each names

All on the install path; each rides with a test on the real installer (H-94's bench) and with the rehearsal's new
`test-boxes` step on the real path (below). Kinds as D-1091; the H-94 page's install.sh table has a row for each.

| Guard | Kind | Harm |
| --- | --- | --- |
| `--test-box` with an environment that is not TEST or DEV | (3) | a test-mode switch that weakens PRODUCTION's one-box rule; a test box taken for the real one |
| a folder installed as no test box made one | (3) | a site's box, with its data, turned into a test box |
| a test box beside a PRODUCTION box; an engine that cannot list the boxes | (3) | data typed into the wrong box; a restore or update aimed at the wrong box |
| a PRODUCTION install beside a test box | (3) | the same, from the other side; whatever any variable says |
| `TB_SECRETS_HOST_DIR` on a test box (install and update) | (5) | two boxes sharing a key or a secrets folder |
| `TB_KEK_BACKEND`, a KEK passphrase, `deploy/site/hardening.conf` on a test box | (5) | the host's KEK folder `/run/trialbox` is one for every box |
| the record not written or not read; python3 missing | depends (5) | no project of the box's own, so no volumes of its own |
| the cards file or the cap not written | (2) | its servers take another box's card, which cannot hold both |
| `--port-offset`, `--gpus`, `--gpu-mem-gb` without `--test-box`; `--test-box` with `--rehearsal` | not a stop | a usage error, refused by name on every box |
| `trialbox` without `--box` on a host with several boxes | (3) | a command (a restore, an update) aimed at the wrong box |
| `backup`, `restore`, `restore-drill`, `logs`, the platform commands on a test box | (5) | they name the ordinary box's volumes and network (H106-01) |

## 3. Every host-level thing a box installs, and what it is for a test box

| Host-level thing | For a test box |
| --- | --- |
| the `trialbox` command (`/usr/local/bin/trialbox`) | not linked; `sudo trialbox --box NAME ...` reaches any box (a test box by its name, the ordinary one by its project, `trialbox`); without `--box` on a host with more than one box the command refuses to guess |
| systemd units and timers (`/etc/systemd/system/trialbox*`: the stack at boot, egress, watchdog, weights, ops) | not installed (`TB_SYSTEMD=0`, set by the installer itself): a test box does not come back after a reboot by itself (H106-06) |
| cron files (`/etc/cron.d/trialbox-retention`, the backup's `trialbox-backup` or its timers) | not installed: no backup, no log retention |
| `/etc/logrotate.d/trialbox` and `/var/log/trialbox-*.log` | not installed, not written |
| the host's egress table (`deploy/network.sh`, its state file under `/var/lib/trialbox`) | not applied; the box's internal networks stay closed |
| the host baseline (`deploy/hardening/apply.sh`: input firewall, SSH) and the KEK folder `/run/trialbox` | refused (kind 5): a test box's keys are not sealed |
| the launcher and the box form (`deploy/launcher.sh`, `deploy/box-install.sh`: the first-run code in `/run/trialbox-firstrun`, `/etc/issue.d`, `trialbox-firstrun.service`, the time zone) | no test mode: `--test-box` is an unknown option there, refused by name |
| the one-time values file (the first administrator's password and enrolment code, written to the installer's home when no terminal) | per box: `trialbox-admin-first-sign-in-NAME` |
| the KEK rotation's journal (`kek-rotation.json`) and lock (H-97: a lock on the secrets folder itself) | in the box's own secrets folder; `tools/keys.py`'s default folder is now the box's own project's (`own_volume`), and a test box's keys are never sealed, so it has no rotation |
| the first-run code file (H-97, `box-install.sh`) | the box form has no test mode (above) |
| volumes under `/var/lib/docker/volumes` | per project: `<project>_*` |
| published ports | per offset |
| the engine's image store | shared, read-only: every box loads the same signed bundle; images are the same pins |

## 4. What H106-01 blocks on the bench host

H106-01 (High, open): `backup`, `restore`, `restore-drill`, `logs` and the platform commands are refused on a test
box, because they name the ordinary box's volumes and network. For the bench's planned uses:

| Planned use | Blocked? |
| --- | --- |
| the profile boxes (32, 48, 96 GB), walked in parallel | no: they need no backup or restore |
| the per-stage measurements and the precision comparison | no |
| the full test set and the review runner on their own cards | no: they need no box |
| a walk step that proves backup and restore | yes on a test box: that walk box must be the ordinary box (project `trialbox`, offset 0, no `--test-box`), which is a PoC box beside the test boxes and keeps every command |
| a test box's own logs collection and retention | yes: `docker compose logs` works; the nightly collection does not |

H106-01 stays open and does not hold this card (the integrator, 7124599679: restore is proven on the ordinary box).
Its follow-up is **card H-117: backup, restore and logs for a named test box** (each command on the box's own
project's volumes and network, as `update.py` now does).

## 6. The rehearsal's step (the real path)

`tools/rehearse_box/box.sh test-boxes`, after `missing-key`: a second box installed by the real installer beside the
rehearsal box, `--test-box rh2 --port-offset 3 --mode stub` (CPU only), from the same media. From the container
engine: both healthy; no volume, volume folder, network or published port in both projects; the test box's
containers on its own networks only and mounting nothing of the first box's (and the reverse); its own `tb-secrets`.
`trialbox doctor` refuses to guess (exit 2), `trialbox --box rh2 doctor` says TEST BOX rh2. A PRODUCTION install in a
third folder refuses `--test-box`, and (with `COMPOSE_PROJECT_NAME` and `TB_ENV=TEST` planted) refuses the host
where the test box runs, nothing loaded. Then `testbox remove --name rh2 --yes`: no container, volume or network of
its project left, its folder gone, the first box's volumes the same and healthy. The step prints its own seconds.
**Its first run** (CI, job 138170206562) stopped at the second box's bundle load: the update path read the fresh test box as PRODUCTION (no deploy/.env yet) and refused the rehearsal bundle (H106-10); `ComposeBox.environment` now reads the record as TEST until deploy/.env says, as it reads the rehearsal mark. **Before that, not run by the card** (no Docker in its container): its added time is not measured; the second install loads the
bundle again, so a few minutes are expected (H106-05).
