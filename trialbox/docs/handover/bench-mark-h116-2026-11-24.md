## 1. The design

The mark is **BENCH**, not an environment: `TB_ENV` stays PRODUCTION, so no PoC leniency applies and every rule
that keys on PRODUCTION holds unchanged. It is shown as "PRODUCTION · BENCH (real data, bench host)" on every
console page (banner and footer), in `trialbox doctor` (a standing WARN line) and in the install's last lines.

| Part | Where |
| --- | --- |
| the option | `deploy/install.sh --bench` (BENCH block, after TEST-BOX): refused with a caller's `TB_BENCH`, with `--test-box`, with `--rehearsal`, and on a box that is not PRODUCTION |
| the record | `deploy/site/bench-box.env`, written by `tools/trialbox/benchbox.py write` (root's, 0644, fsynced, renamed into place): the install's first line, `TB_BENCH=1`, the folder, the time |
| the check | `benchbox.check`: a link or another kind, another owner, writable by group or others, no install's trace, another folder's, `TB_BENCH` in deploy/.env with no record, a box that is not PRODUCTION, a test box, a sending identity: each refused |
| where it is checked | every install (BENCH, then ENV-BENCH once deploy/.env is the site's), every start (`deploy/settings_guard.sh`, before the systemd unit and `tools/apply_update.sh` start the stack), doctor (`check_bench_box`, on the rehearsal line) |
| what it changes | the host listing (`testbox.boxes`) names a box whose mark holds `bench`: a test box installs beside it; a PRODUCTION install with the mark goes on beside test boxes (a note line names them). A refused mark counts as PRODUCTION |
| sending identity | `SMTP_HOST` other than empty, `localhost`, `127.0.0.1`, `::1` or the test stack's sinks, or `SMTP_USER` set: refused (a bench box sends no mail outside the host) |

## 2. Tests

`tests/unit/test_bench_box_h116.py` (15 test functions, 35 tests with their cases; each of 8 planted faults fails at least one):

- the record and its check: written as the option writes it; each kind of hand-made mark refused (no trace, extra
  key, another value, another time, mode 0666, another owner, another folder's, a link);
- the mark is a PRODUCTION box's with no sending identity (TEST, VALIDATION, a relay, a relay login, another value);
  the option writes nothing on a box that may not carry it;
- the install (H-94's bench with H-106's engine stand-in): `--bench` goes on beside a test box where the same
  PRODUCTION install without it is refused; a caller's `TB_BENCH` (even empty), `--bench` on TEST or VALIDATION,
  with `--test-box` or `--rehearsal`, a hand-written record and a sending identity are refused;
- every start: `settings_guard.sh` refuses a mark with no record, on a box made TEST by hand, and a record others
  may write; a box with no mark is not asked;
- doctor and the console say "PRODUCTION · BENCH (real data, bench host)"; never on a box that is not PRODUCTION;
- **the third kind in H-106's invariant** (`test_a_bench_box_test_boxes_beside_it_share_nothing`): the engine lists
  the bench box as `bench`, a test box installs beside it and shares no volume, network, published port or secrets
  volume with it; with its mark refused the bench box counts as PRODUCTION and the next test box is refused;
- `test_the_mark_changes_no_production_rule`: `TB_BENCH` is read in seven files only, none a protection.
- the console's banner for each environment value (DEV, TEST, VALIDATION, PRODUCTION, PRODUCTION with the mark, unset): the bench words only on PRODUCTION with `TB_BENCH=1`;
- H116-01 (the integrator's ruling 7142529568): `benchbox.py` and `settings_guard.sh` are on the rehearsal step's path list; a change to either alone runs the step.

**The real install path (high-risk):** the rehearsal job's `test-boxes` step (`tools/rehearse_box/box.sh`), with
the test box `rh2` running, adds: a caller's `TB_BENCH=1`, `--bench --environment TEST` and a hand-written record
refused; `--bench --environment PRODUCTION` goes on beside `rh2` (its note line names it) and stops at the
signature check of a stand-in bundle, nothing loaded, its record root's and 0644. The harm it names: a switch that
puts a real-data box beside a test box without the owner's install option.
