## 3. The acceptance results table (item b)

No acceptance proof file existed on this base (grep for "acceptance" and "proof" under `docs/` and `tools/`), so the
card defines the form in the tool's docstring.

- **A proof file** is `tb-acceptance-proof/1`. It gives a criterion, a title, a result (green or red) and the path of
  its evidence.
- **An evidence file** is what the run wrote. It gives the commit and the counts: passed, failed, skipped, xfailed and
  strict xfail.

`python -m tools.results_table --proofs DIR --commit SHA [--out FILE]` refuses with exit 2, one line per row and no
table written, when a row:

- names no evidence;
- has no evidence file;
- has evidence that names another commit;
- has evidence that names no commit;
- is green while its evidence counts a failure;
- is green while its evidence passed nothing.

A green row shows its skips and strict xfails beside the word ("green, 3 skipped, 2 strict xfail") and in their own
columns. No clock is read.

There is one test per refusal, plus one for the counts and one for the command's exit. They failed first (no
module). Each refusal was then switched off in turn, and only its own test failed.

## 4. The release bundle's fresh build (item c)

H-143 already holds `make release-images`: one pull of every pinned base before the first build, and every build with
`--no-cache` and without `--pull`. It also holds the `release-bundle` rule to name `release-images` before
`release-gates`. Each of these was removed in turn and H-143 run again:

| Change | H-143 | This card's tests |
| --- | --- | --- |
| The pull loop without `\|\| exit 1`: a refused pull is passed over | 20 passed | fails: a refused pull must stop the release before any other pull or build |
| One outside base without its digest (the db base) | 20 passed | fails twice: the whole run's pulled set, and every outside base pinned |
| One build without `--no-cache` (jvm) | fails | fails |

Added in `test_release_bundle_fresh_build_m10.py`:

- the whole `make -n release-bundle` run: every pull before the first build, the bundle after the last, every build
  uncached and without `--pull`, and the pulled set equal to the outside bases of the Dockerfiles that run builds
  (read from its own `-f` arguments);
- every outside base of those Dockerfiles pinned by digest;
- a refused pull stops the release. This one runs `make release-images` for real, with a stand-in `docker` that
  refuses every pull and logs each call.

Not changed, for the integrator to weigh: `make release-bundle NO_CACHE_ARG=` on the command line would still empty
the no-cache flag in the sub-make. That is a deliberate override, not a step going missing, so no test was added.
