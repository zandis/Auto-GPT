## 3. Trains

1. A lane hands over with `train-ready: #<n> <full sha>` and pushes nothing after it.
2. The integrator builds `train/<n>` on master: `git merge --no-ff` of each head. It keeps every side's lines in the
   files every lane appends to (`REGISTRY.md`, `CHANGELOG.md`, the Makefile's target list, runbook tables,
   `limits_allow.yaml`) and regenerates generated pages (`python -m tb_common.erasure --write`). A conflict in code
   goes back to the lane that owns the later card; it merges the train's tip and pushes once.
3. The branch is pushed WITHOUT a pull request while it is being built (no CI runs); lanes stack fixes on it.
4. Before the pull request is opened, on the combined tree, output to files: ruff check and format, mypy, decisions
   index, doclint, data scan, contracts, `tools.limits_lint`, `tools.security_scan sast`,
   `tools.supply_chain allowlist-check`, the Makefile's cross-card list, every unit test file the cards touch,
   `tools.goldens --check --profile ci`, `tests/integration/test_e2e_simple.py`. On 2026-11-12 each of these, when
   it was missing from the local set, let a red reach CI.
5. The pull request is opened (not a draft; `train/*` runs the full tier). The train is then closed: a card that
   missed it waits for the next. Reopening is right only for a fix of a red the run itself showed.
6. Green: merge with a merge commit and `expectedHeadSha`, so the card pull requests show as merged. Branch
   protection on `master` requires `unit`, `lint`, `types`, `docs`, `contracts`, `data-scan`, `cross-card`.
   **Train 4 renames checks: at its merge the owner removes `lint`, `types`, `docs`, `contracts` and adds
   `checks`.**

Push rule for lanes (CI minutes are billed; 2026-11-12 cost about 30,000 runner minutes): at most three pushes per
card (claim, complete, review fixes); no merge of master into a branch; pull requests stay drafts.
