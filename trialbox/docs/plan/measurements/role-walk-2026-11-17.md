## How a cell is decided

- **The gate of a console route** is read from the running app: the walk wraps `permit` and records every action the route asks while it answers, outside templates and outside the calls every page makes for the session and the menu. Among those actions, the gate is the one (or the pair, both or either) whose matrix answers fit the walked answers best. A route that asks no action is open to every signed-in account. The orchestrator names its action on the route (`require_actor`), so its gate is the declared one.
- **Expected** is `permit(role, gate, standing)`, with the column's standing in GZQO read from the matrix's header (log names a PI; the PI; the sub-investigator's ticks; a monitor grant). Signed out: refused. A route that names GZQO's data (`{rs}`, `{ruleset}`, `{pid}`, `{job_id}`, `{record}`): refused for a column that does not see GZQO.
- **Got:** refused = 401, 403, a redirect to sign-in, or 404 for a column that does not see GZQO on such a route; allowed = 2xx or a redirect elsewhere; a 400/409/410/422/429 is allowed only when the gate was asked in that request and said yes (validation after the check), refused when it said no, else unclear; every 5xx and a 404 for a column that sees GZQO are unclear. On the orchestrator: refused = 403 from the dependency with reason `right`; past it = any other answer.
- **Limit.** The console declares no action per route, so its gate is inferred. A route that asks the wrong row consistently would look right here; the inventory below names each route's gate for a reader to check, and the test compares it with the rows `tests/console/test_role_route_matrix.py` names by hand.
