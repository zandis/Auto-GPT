# Traceability, a dry run on master (card V-15, lane V, 2026-11-17)

Plan 8 release criterion 9 asks for "the validation pack generated by command (requirements, risk, traceability
with real results, IQ and OQ)", activity V18. This page is a first, dry run of the traceability part on master, to
find what is missing before the release candidate. It reports; it changes no product code and no document of the
pack.

Every table and count below sits between `trace_dry:begin` and `trace_dry:end` lines. `python -m tools.trace_dry
--write` writes them from the repository; `python -m tools.trace_dry --check` (and `tests/unit/test_trace_dry.py`)
fails when a block differs from `traceability-dry-2026-11-17/trace.json`, when a count differs from its rows, or when
a test the json names is not in the committed collection.

## Decisions that state a rule and that no test cites

its paragraph in `docs/DECISIONS.md`) contains one of the words must, never, refuses, is refused, only, and whose
number no file under `tests/` writes as `D-n`. Ranked by a safety score: 3 for each group named in the title, 1 for
each group named in the text; the groups are screening exclusion, PHI and masking, roles, audit, erasure and
opt-out, EDC signing. It is a heuristic: a test can show a rule without citing its number.

## How this relates to `tools/gen_traceability.py`

That tool is not changed. Run here with `--strict`, it says "clean", and after a plain run the working tree was
unchanged: its committed CSV equals a fresh run. It reads only the superseded plan, and it writes "planned" as the
status of every row (`tools/gen_traceability.py:131`). This tool reads results; the owner of the pack can fold that
into one generator.
