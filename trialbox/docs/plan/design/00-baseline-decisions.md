## 1. Document IDs

One scheme: `TB-DS-nn` for design documents, `TB-REV-nnn` for reviews, `TB-PLAN-nn` for plans, `TB-TMPL-nn` for templates, `TB-REC-nn` for records. `SIMPLE-PLAN.md` is TB-PLAN-02; it carries its own short control table and a register row. Each document starts with a control table (ID, version, date, owner, status, approvals) and ends with a change history. The register is TB-DS-00R (`00-document-register.md`). File numbers order the files on disk and are not IDs: `13-` holds TB-PLAN-01, `14-` TB-TMPL-01, `18-` TB-TMPL-07, `19a-` TB-REC-01; the ID in the control table is the one to cite.

## 2. Build stage: the five steps

The build follows `SIMPLE-PLAN.md`: Claude builds and tests on synthetic and public data in five steps, each one pull request. **`20-build-map.md` (TB-DS-20) is the single statement of what each step contains**, which screens it needs and when it is done. **Build tags (the one legend for the whole set; every other document cites this paragraph):** **S0** built today and kept working by the existing tests; **S1–S5** built in that build step; **H** hospital stage, only when a hospital uses real patient data; **L** later. A cell may keep its earlier tag as "(was M1)", "(was M2)", "(was C)" or "(was SC-nn)" for history; a row split by letter suffix carries "(split from <root>)". M1/M2/C survive only inside §2.H and the hospital-stage documents (TB-PLAN-01, TB-DS-15, TB-TMPL-01, TB-TMPL-07), where they name hospital-stage releases. The synthetic hospital is specified in `21-synthetic-hospital-spec.md` (TB-DS-21). The only build gate is `e2e_simple` (TB-DS-04 §3.4.1) plus the benchmark not getting worse (N-11, N-12).
