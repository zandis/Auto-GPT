# D-1220 A console text key cannot go wrong silently (J-1, review L-4, journey review A-M4 and G-5)

- **Task:** card J-1 of lane J (journey review row R4, full review F24): "The check fails the build on a key defined twice with different text and on a key used that nobody defines. Fix the conflicting doubles and the two places where a raw key shows on a page." · **Date:** 2026-11-17
- **Decision:** `python -m tools.text_keys` reads every definition of a console text key where it is written (each `EN`/`JA`/`ZH` dict of `services/console/*.py`, a dict passed to their `update`, a `{"en": …}` table, the label tables `i18n_audit` joins in a loop, a `**{…}` unpack), so the loser of a silent `dict.update` override and a key written twice in one dict are both seen. It fails on (1) one key, one language, two different texts; (2) a key or text the served catalogue (every console module imported) holds that no definition it read wrote, so a new way of joining keys cannot slip past (1); (3) a literal key a template (`t('…')`, the menu's `item(…, 'key', …)`) or the Python (`translate(lang, "…")`, `t("…")`) asks for that no catalogue has; (4) a dynamic family (`t('life.vstate.' + v.status)`, `f"life.state.{s}"`) that is neither checked member by member (`FAMILIES`: every value the code can produce, read from the tuple the code uses or from the assignments in the function that produces it) nor listed in `UNCHECKED_FAMILIES` with its reason, or one no key starts with. A family asked with `t_or` has its own fallback and is not listed. The test is `tests/unit/test_text_keys.py` (marked `guard`: the `checks` job runs it on every tier; also in `make cross-card`), and `make lint` runs the tool. Under the test suite (`TB_STRICT_TEXT=1`, set by `tests/conftest.py`) `translate` raises `MissingText` on a key no catalogue has, so a page a test renders cannot show a raw key; a box leaves it unset and keeps showing the key, so a missing text never takes a page down. A page that wants its own fallback asks `lookup` (Python) or `t_or` (templates), never "the text equals the key".
- **The doubles:** master had 30 keys defined twice with different texts (87 key-language pairs; the review counted 15). Two pages meant different things by `edc.title` and `edc.help` (G-5: the administrator's EDC connection page and the coordinator's prefill page): the connection page has `edc.conn.title` and `edc.conn.help` now. In the other 28 one text had replaced the other on the same page by a later card; the text shown today was kept and the overridden definitions were deleted, so each key has one definition. 54 doubles with the same text (key and language) are listed by the tool and not failed.
- **The raw key:** A-M4: `datacore.lifecycle.visit_status` gives a visit "unplanned" while its anchor date (enrolment or consent) is not recorded, which `VISIT_STATES` does not list; `life.vstate.unplanned` reads "No date yet" (日付未定, 尚無日期).
- **Left:** 184 dynamic families are listed, not checked member by member: their suffix is a value of stored data or of a service's answer, a refusal code, or the word a page is sent back with after an action; the strict test run checks what the tests render. Keys handed to a template in a variable (an error key a route passes) are checked only at run time, the same way.
- **Held by:** `tests/unit/test_text_keys.py` (no conflicting double, no unseen source, no missing literal key, every family checked or listed; the reader sees each kind of mistake; the strict `translate`), `tests/console/test_text_keys_pages.py` (the participant page with a visit that has no date yet and `/admin/edc`, rendered in en, zh-TW and ja); synthetic data only.
