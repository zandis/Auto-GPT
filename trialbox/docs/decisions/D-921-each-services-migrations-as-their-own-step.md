# D-921 Each service's start-time migrations run as a step of their own, before the services start

- **Task:** T-695's rest (F-10 of `docs/reviews/2026-11-11-scale-timeouts.md`), lane B2 · **PR:** `agent/T-695b-service-migrations-own-step` · **Date:** 2026-11-16 · **Status:** accepted · **Builds on:** D-752, D-624, D-486

1. `db-up` gets a fifth step, "service stores", after "owned schemas". It runs `python -m orchestrator.migrate_stores` in a one-off container (`compose run --rm --no-deps`) of each service in `STORE_SERVICES` that the box runs. Each container has the service's own image, settings and database role. The step opens and closes the stores the service opens before it answers `/healthz`: orchestrator `orch`; mail-gateway `mail`; gateway `trace` when the trace store is on; criteria-compiler `omop` in vocab mode; console `auth`, `site`, `team`, `optout`, `app`, `feedback`, `sae`, `breakglass` and `tuned`.
2. A run's limit is a restore's limit of the trial database (`backup_schedule.step_timeout` of its size, D-455), with no limit when the size cannot be read. The updater's limit on `db-up` and the whole update's limit each add one such limit per service. A migration of 600 s therefore never meets the health wait (20 s start period plus ten 15 s retries) and never rolls the update back.
3. `trialbox migrate` runs the step too. The services still migrate at start and find nothing left to apply there. A store a service opens later (on a request, a job or a timer) still migrates there: it holds no health wait.
4. The floor stays 0. The step runs in the new tree's own `db-up`. An updater from before `db-up` leaves the migrations to each service's start, as before.
5. Tests: `tests/unit/test_t695_service_migrations.py`. It checks that the lists match each other and the role script. It runs the step's commands, order, limits and refusal with a fake runner. Against PostgreSQL, the console's real start and each other service's start-time store apply no version after the step; dropping one store from the list fails the test. `test_update_dbup.py`, `test_update_minseq.py` and `test_t695_update_stop_boot.py` name the step and its limits.
