- **Decision:** one `ai.confirmed` per verdict a model answered (its `prov` not empty), `record_ref` (ruleset, version, job, pid, crit), `by` the user name, written with the mark's own audit event inside the mark's transaction. The table, as the integrator ruled (2026-11-17): Approach → `confirmed`; a review of an exclusion ("this is wrong, send to review") → `rejected`, on the named criterion's verdict, else on every failing verdict of the row that has `prov`; Not suitable now → no event (its reasons are each site's own and may have nothing to do with the model, and the chain never infers a judgement on the model's answer); Need info, Not now → no event; an Approach taken back (Withdraw, Undo, or another mark in its place) → `withdrawn` (the integrator's ruling (b), lane A2's decision in #999), naming the record and calls of the confirmation it takes back, on the list it was made on, and an Approach put back by an Undo is `confirmed` again; nothing maps to `changed`. A verdict with `prov` empty (no model) or absent (a list from before the field) writes nothing. Files outside the card: excluded patients are on no candidate list, so the orchestrator's excluded list keeps each failing verdict's `prov` (`orchestrator/scenarios/screen.py` `excluded_doc`, one line and its test).
