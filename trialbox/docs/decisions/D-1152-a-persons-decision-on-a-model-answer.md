# D-1152 A person's decision on a patient a model answered is `ai.confirmed` (D-989, the console's part)

- **Task:** D-989 point 3, handed over by lane A2 through the integrator: when the console records a PI mark or an excluded review on a patient with model evidence, it writes `tb_common.provenance.confirmed` for the verdict, by pseudonym. · **Date:** 2026-11-17
- **Decision:** one `ai.confirmed` per verdict a model answered (its `prov` not empty), `record_ref` (ruleset, version, job, pid, crit), `by` the user name, written with the mark's own audit event inside the mark's transaction. Approach is `confirmed`; Not suitable now is `rejected`; a review of an exclusion is `rejected` for the named criterion's verdict, else for every verdict that excluded the patient. Need info, Not now, Withdraw and Undo decide nothing about the model's answer: no event, so it stays unconfirmed. Nothing in the console maps to `changed`. A verdict with `prov` empty (no model) or absent (a list from before the field) writes nothing. Excluded patients are on no candidate list, so the orchestrator's excluded list now keeps each failing verdict's `prov` (`screen.excluded_doc`).
- **Left:** the mapping of Not suitable now to `rejected` is put to the integrator (a site's reasons may be non-model ones); SCREEN's `ai.used` covers the listed rows only, so an excluded patient's verdicts have `ai.confirmed` but no `ai.used` until lane A2 widens it (MICROBATCH's does).
