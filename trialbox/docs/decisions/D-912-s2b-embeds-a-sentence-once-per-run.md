# D-912 S2b embeds a sentence once per run and compares in numpy

- **Task:** note-processing review of lane G's SCREEN run (2026-11-15); builds on D-900's cache in the orchestrator; **Date:** 2026-11-15; **Status:** reserved
- **Decision:** S2b embedded `[query, *every window sentence]` for each zero-hit (patient, criterion) pair: a patient's sentences once per zero-hit criterion, and again in every round of a two-phase run (each round reruns the cascade). A run now keeps the vectors it got by the embedder's model and the text's sha256 (`matching.cascade.s2b_semantic.SentenceVectors`) and sends only the texts it has not embedded; SCREEN passes one memo to every round of its run, so the verifier's round sends none. A vector is kept as the embedder gave it (float32 when that loses nothing, as a model's output is, about 4 kB; float64 otherwise), so the vectors read back are the vectors embedded, and the scores are the same. The similarities are computed in numpy, with `cosine`'s formula (a zero vector's norm read as 1). A model that changes during a call is never mixed with the one before: the call's texts are embedded again under the new model. `CascadeConfig.s2b_memo` (on) turns it off for the comparison test. D-900's least-recently-used cache in the orchestrator stays: it serves the next protocol of a job; this memo serves the run whole, without eviction.
- **Not here:** a persistent store of judged pairs (CAS-5) or of sentence vectors, and the stored-vector path (`vec.s2b`); both need decisions of their own.
- **Test:** `tests/unit/test_s2b_one_embed_per_sentence.py`; `tests/unit/test_cascade_pipeline.py::test_s2b_embeds_each_sentence_once_with_the_same_answers` (scores, prompts and answers equal with and without, feasibility and SCREEN; fewer texts sent; a second round sends none).
