# D-863 The mail outbox asks before it sends a job's files (NEW-MAIL-1; the integrator's ruling of 2026-11-16)

- **Task:** NEW-MAIL-1. The adversarial review of T-206b part 2b found that a mail held at publish (the SMTP server down) and sent later by the drain, or by `trialbox mail resolve KEY --resend`, read the job's patient-level files with no check of the opt-out register. It could name a patient who had opted out in between. The integrator ruled the design: one choke point, fail closed, and the erasure path for a held mail's files. · **Date:** 2026-11-16
- **The choke point:** every attempt to send goes through `Gateway._attempt`: publish, a queued try, and a person's resend. Before it builds a mail of a job's patient-level files, `_still_current` asks the orchestrator `GET /jobs/{job_id}/outputs-current`, keyed on the job id the outbox row already carries. The answer is a yes or no, never a patient or a count. The route is in `reads_without_patient`, and the mail gateway is its only caller (`route_callers.yaml`). One judgment serves the orchestrator and the worker (`tb_common.patient_files.naming`): a per-patient file by its patient, a text file by its content in any case, and a compressed file by the job's text files. A mail of counts is not asked.
- **Fail closed:**
  - A no is held as `failed` with the typed reason `patient_files.HELD`; it is never tried again by itself, and a resend asks again.
  - No answer, an error, or no job to ask about is held as `queued` with the reason `NO_ANSWER`; it is asked again later.
  - Only a yes sends.
- **The erasure path:** the opt-out worker's new clear `held_mail` finds each mail held as `failed` with that reason and deletes from the object store each of its attached job outputs that names a patient opted out now. A file naming no one stays. The console already withholds the same file (D-860). An outbox it cannot reach is never called cleared. `objects:outputs` leaves the owed list (49 to 48): it is withheld on read and kept until retention (D-513), with this clear. The pinned clear list (`test_erasure_registry`) and `KNOWN_OWED` (`test_erasure_seed`) move.
- **Held by:** `tests/unit/test_the_outbox_asks_before_it_sends.py`, synthetic data only. It covers SMTP down at publish, then an opt-out, then the drain; the same with `--resend`; an orchestrator that does not answer; a gateway with no way to ask; a mail of counts; the orchestrator's judgment; the worker's drop; and an unreachable store. The callers pin moves to the new route.
