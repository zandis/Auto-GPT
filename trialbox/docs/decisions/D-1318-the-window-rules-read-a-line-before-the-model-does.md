# D-1318 The window rules read a criterion's time expressions before the model's windows are trusted

- **Task:** OPT-1 W3. A graded sample of 297 window lines (public registry text) put the model's windows at 70.4 % right; deterministic rules with the model as fallback read 90.9 % right on a blind second judgement (rules alone 87.2 %, 259 of the 269 lines they claim). **Date:** 2026-11-27. **Status:** reserved (the number is a placeholder; the integrator may renumber).
- **Decision** (`ir_extract/window_rules.py`, the first step of the per-criterion loop in `postprocess`, standard library only).
  - The rules read every temporal expression of the line: value and unit as written, anchor, and kind (`window`, `duration`, `none`, `unparsed`). A line with any expression they do not fully read is `unparsed`: nothing is changed. They abstain on an anchor that is no event name (a cut-off verb phrase, a composite of two events, "at least 7 mg/dL"), on a window counted from an index disease ("synchronous or metachronous"), and on a bare "within N" before a clause that names its event (the anchor may be shared). A line in Chinese, Japanese or Korean is left to the model: the rules read English.
  - **A window the line states is the rule's** when it has a form in days from the run's date: no event named ("in the past 3 months", "2 years ago"), a side of the anchor (a bare "within N" has none, and the rules never pick one), a whole-day unit (hours and minutes have none), not an exact offset, not a course ("for at least 12 weeks prior to ..."), not an open future end. It replaces the window of the one atom of a criterion that has just one atom (age and sex atoms do not count; a duration-in-window atom is never written, but it is one of the atoms the window may belong to), and is added when that atom has none. Review 2: a window counted from a named study date (`screening`, `randomization`, `enrollment`, `consent`) is not the run's date, and the extraction's window has no other anchor, so where the rule would write one the criterion goes to a person (`window_anchor_unsupported`); a model window that agrees is left as it is. A negative amount ("-7 days", D-914) and two study dates in one window ("before screening or first dose") go to a person (`window_negative`, `window_anchor_alternatives`). Windows are compared in the line's own unit (96 hours is not two days); a comparator is read whole ("no more than" is a within) and a strict bound is one day inside the inclusive one; an exact offset is compared on both signed ends; with several windows each distinct one must be on some atom (`window_unattached`). Equal means within 2 % (and a day): 12 months is the model's 365 days as well as 360. With several atoms the line does not say which carries the window: atoms are compared, never written (`window_disagrees`, `window_unattached`); several windows are compared with their signed side.
  - **A window counted from another event** ("within 30 days after surgery" on a chemotherapy atom) is not the window counted from the index date: flagged `window_anchor_event`, never written. When the atom is that event ("at least 14 days since surgery" on the surgery atom) the window is compared by length.
  - **A window counted from the study's own dosing or end** (`first_dose`, `last_dose`, `end_of_study`) is not a date before pre-screening: a mixed criterion keeps its note question and the notes decide, any other goes to a person (`window_anchor_unsupported`); an unbounded "prior to the first dose" does so only when the model gave a window.
  - Every change or disagreement flags the criterion (`window_rules_override`, `window_disagrees`, `window_unattached`, `window_anchor_event`, `window_anchor_unsupported`, `window_negative`, `window_anchor_alternatives`) and so `needs_review`.
  - **A window the line never states** (no time expression, or only a duration: "stable dose for 3 months" is how long a state has lasted, not a window, STATUS ruling 2026-11-27) is left alone by default. The stand-in extractions the committed rulesets were built from put a recency window on every "latest" lab and on pregnancy (-365, -180, -90, -280 days), which the prompt does not ask for; dropping them (`window_not_in_text`) and refusing a window on a line with no word about time (`window_invented`, check (iii)) are in the code behind `window_rules.DROP_UNSTATED_WINDOWS` (false) and change those rulesets' regenerated output, so they wait for a ruling.
- **IR 3.x:** `Anchor` gains `enrollment`, `consent`, `first_dose`, `last_dose`, `end_of_study` (additive; the two schema files are regenerated). `downgrade_to_v1` refuses them by name (`NotV1Expressible`); `semantics.one` and `semantics.window` refuse them by name (`CompileError`), so a person reads the atom. No compile path for them yet.
- **Compile checks** (OPT-1 §3), in `semantics.window` and `semantics.lower`: (iv) a window whose reach or width is more than 3,650 days, or more than 72 hours counted in hours, is refused; (v) one length stated as both the window and the atom's `duration.min_days` is refused. (v) is narrower than "duration and window are exclusive": a medication course of N days inside a longer window is the existing, valid meaning of `duration` (`semantics` module doc). (iii) is the lint above.
- **Not chosen:** letting the rules attach a window to one of several atoms; converting hours or minutes to whole days; reading `enrollment` or `consent` as compile-ready in IR 3 (no ruling).
- **Test:** `tests/unit/test_window_rules.py` (50 hand-written readings and 12 abstentions of public registry text, other readings, the 87 adjudicated rule-versus-model pairs: the 83 the third reader found right are read as adjudicated, the 4 found wrong are not claimed, the reconcile and lint steps and the defects the first review found), `tests/unit/test_window_rules_postprocess.py` (the step in `postprocess`, the enum, checks iv and v).
