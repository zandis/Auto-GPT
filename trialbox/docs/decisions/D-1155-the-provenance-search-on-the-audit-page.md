# D-1155 The audit page searches which records a model, build or prompt touched (D-989, the console's part)

- **Task:** D-989's reading (2026-11-16, #639): the search is on the console's audit page, steward and admin, because the answer names patients; lane A2's step 2c (#999, D-997) gives `tb_common.provenance_index.search`. · **Date:** 2026-11-17
- **Decision:** `GET /audit/provenance` runs `provenance_index.search` (model, build, prompt sha, or prompt id with version; at least one, else no search) over a short-lived connection to the trial database as the console's role (lane D's grant: USAGE and SELECT on the schema), the newest 200 records (the CLI lists all). A new matrix row `audit.provenance`: the data steward and the privacy office (as `audit.browse`) and the administrator; a reader without `audit.ids` (the administrator, D-280) sees every record with its pseudonym taken out, so "which records did build X touch" is answered without naming a patient to the role that sees none. Each search is audited `console.provenance_search` (the filters, how many rows, whether pseudonyms were shown). An index that cannot be read is said on the page (503), never a server error.
- **The adversarial review:** for a reader without `audit.ids` a pseudonym is masked anywhere in a record and in who decided, not only under its key; a filter is an id (letters, digits and `. _ : @ / + -`, a prompt version with its prompt id), so no free text is searched or written to the chain; a search that fails is audited too (`error`).
