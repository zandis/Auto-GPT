## 1. Summary

The gateway design is sound: one path to a model, class labels, a perimeter rule checked at look-up time, forced
sampling, pinned builds, an audit record per call. The weak points are at the edges of that design.

Counts: **Blocker 1** (registered), **Critical 3** (1 new, 2 registered), **High 15**, **Medium 23**, **Low 4**. Total 46.

Top 5:

1. **LLM-002 (Critical, new).** When the judge server fails, the gateway answers the judge's question from the
   verifier build. The verifier then "confirms" its own answer. The pair reports agreement and may exclude. Confirmed
   by a run with the install's default settings.
2. **LLM-007 (High).** `install.sh` pins whatever files are in the model folder as `champion`. Nothing compares them
   with the vendor's measured hashes. A 16-byte fake file was pinned as the judge in a run.
3. **LLM-015 (High, new).** No code reads the build's context length. The full-record fallback sends up to 28,000
   tokens to a 16k (Spark) or 8k (5090) server. Chart reading accepts 60,000 characters. The stub has no limit, so
   no test sees it.
4. **LLM-036 (High, new).** "Perimeter" is a label in a file. The address of a perimeter endpoint comes from an
   environment variable and is not checked. With one extra egress entry the box sends D3 text off the box and
   records it as on-box.
5. **LLM-034 (High, new).** Patient notes and protocol text go into prompts with no "this is data" rule (one prompt
   of twelve has it), the injection guard role is never called, and both models read the same text.

Also important: the B200 has no profile, no registry build and no measurement (LLM-011, LLM-027); the stub's judge
only understands four zh-TW sentence patterns, so ja and en notes always come back "unknown" in a stub demo
(LLM-045); the trace store keeps note text for 90 days and is on by default (LLM-040).

## 5. What is good (do not change)

* One path to a model: `tb_llm` → gateway. The unit test that scans for direct model calls exists (PR #68 extends it).
* `may_reach` is checked at look-up time and the shipped routing file is linted; D3/D4 never match an external
  zone, guard roles never route outside, an external endpoint without a G5 record is not routable.
* Fail-closed registry: an unpinned build routes nothing; a site override cannot add builds or fields.
* Forced sampling for all schema roles; provider routing only from the pin, never from the caller.
* The call ledger holds hashes and labels, not text or headers; it is written before the response.
* `tb_common.pair.combine` is one small function used by every path; disagreement, a missing quote and a model that
  did not answer all become `unknown`, never an exclusion.
* `effective_note_block`: without a verifier or a passed canary a note answer cannot exclude.
* The sleep swap refuses to send a call to a sleeping model during a held run instead of falling back.
* `pin_model` refuses pickle weights and Python files; the serving record refuses a capped card as a measurement.
* PR #75 (prompt registry) and PR #64 (wrong-exclusion gate with the product's own prompt and parser) are well
  built; PR #68's guard closes vLLM's unkeyed routes; PR #85 refuses to start on unmeasured serving values.
* vLLM runs offline (`HF_HUB_OFFLINE`, no usage stats) on an internal network; the model folder is read-only.
