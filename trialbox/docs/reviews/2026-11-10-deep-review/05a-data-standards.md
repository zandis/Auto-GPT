## 1. Summary

TrialBox names many standards. Three are used with care: FHIR R4 as the internal record shape, JP Core through an offline rule check, and ODM 1.3.2 for the EDC export (schema-valid). OMOP is a CDM-shaped store with source codes only. MedDRA, CTCAE, SDTM, Define-XML and SNOMED CT are absent, most of them by decision.

The data path works end to end on synthetic data, and every checker passes. The weak points appear where real hospital data differs from the synthetic data: units, Japanese encodings and result spellings, code-system editions, and drug codes in Japan.

Counts: **35 findings: 1 Blocker, 0 Critical, 9 High, 18 Medium, 7 Low.**

Top 5:

1. **STD-001 (Blocker, in PR #70).** The adapter never reads a lab row's own unit. It stamps the lookup's unit and a fixed factor. By a run: creatinine 88 µmol/L leaves the adapter as 88 mg/dL. The engine-side fix of CR-001 cannot see this, because the wrong value is already labelled with the right unit.
2. **STD-020 / STD-021 / STD-022 (High).** The SS-MIX2 reader fails on common vendor bytes (half-width kana, NEC special characters, Shift_JIS) and one such file stops the whole night. It does not read OBX-11 (a deleted result counts), has no fallback for the sample time, and maps no Japanese qualitative result (陰性, 陽性, (-)), so hepatitis B, TB and pregnancy tests can never be decided in Japan.
3. **STD-030 (High).** OMOP standard concept ids for conditions and drugs can never be filled by the current rule, even after the Athena load. Today 100 % are 0 (by a run). The store is not usable by OHDSI tools or network studies as built.
4. **STD-040 (High).** The five committed rulesets hold short exact code lists from before the family expansion (rheumatoid arthritis = 5 codes; today's compiler gives 418 and two families). A patient coded with a sibling code fails the inclusion and is excluded.
5. **STD-060 (High).** The REDCap client expects JSON for `content=version`; REDCap answers plain text. The link fails at first contact with a real REDCap (by a run against a mock that answers as documented). The simulator answers JSON, so tests pass.

Also High: STD-010 (Japan's ICD-10 handled as ICD-10-CM), STD-013 (a death flag without a date is not read), STD-042 (no YJ to ATC source at scale).

## 6. What is good (do not change)

- The OMOP DDL is the official v5.4.2 text, pinned by sha256 and refused when changed; extension tables are kept apart with a `tb_` prefix; local concepts sit at 2,000,000,000 and above and are never standard.
- The JP Core check: rules derived from a hash-pinned package, reproducible (`--check` passed), offline, no JVM, run at every ingest with the result written beside the snapshot.
- Licensed Japanese masters are never shipped: the site loads its own release with version, file hash and encoding recorded (`adapter.licensed`).
- Unknown stays unknown: a text result, a code no list can read and a suspected diagnosis (PRB-13) never become a failed test. The fixes above must keep this.
- SS-MIX2 versioning is right: newest time stamp per record wins, condition flag 0 is a delete, and deletes become tombstones.
- Reference data of PR #65 is registered with source, licence read at the source, version and sha256, and a parser that refuses another licence.
- CQL and SQL are generated from one IR by templates, never by hand or by a model; value-set versions are in the CQL header.
- The ODM export writes only signed values, each with its audit record, signature and a citation id with no clinical text; it is schema-valid.
- The REDCap client never logs the token, imports with `overwriteBehavior=normal`, and refuses unsupported major versions.
- The catalogue keeps LOINC as code and name only, marks what a site may store per instrument, and leaves OMOP ids blank rather than guessed.
