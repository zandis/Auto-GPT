## 1. Summary

TrialBox is about 66,000 lines of its own Python in `services/` and `libs/` (plus 2,200 generated contract lines), 28,000 in `tools/`, 26,500 in tests, 3,100 lines of Jinja templates, 1,100 lines of its own JavaScript and 2,100 of shell/PowerShell. Its library footprint is deliberately small (74 locked packages, no OS packages in the base image) and the choices it has made are mostly good: FastAPI, pydantic, psycopg 3, DuckDB, sqlglot, HAPI FHIR, vLLM, cryptography, reportlab/openpyxl, APScheduler 3. Where it is home-grown, it is usually because the domain is specific (three-valued eligibility SQL, fail-closed code families, the two-model rule, SS-MIX2 storage layout, era and 民國 dates, Taiwan ID and マイナンバー check digits, the one-GPU sleep swap) and no library covers it. That judgement holds in most places.

Where the review disagrees with the current state:

1. **Authentication** is the one component where home-grown is the wrong call for a hospital product. There is no MFA and no AD/LDAP (review R-04, R-11). An OIDC provider that already does TOTP, WebAuthn and LDAP (Authelia, Apache-2.0, a single Go binary) in front of the console, with the console as an OIDC client (Authlib) and local TOTP (pyotp) as the fallback, removes a blocker for about two weeks of work, and avoids writing MFA, recovery codes and LDAP binds by hand.
2. **The HL7 v2 parser** (92 lines) should be a library. It ignores MSH-2 encoding characters, sub-components and repetitions and decodes anything not labelled `IR87` as UTF-8. `hl7apy` (MIT, 1.3.5 of 2024 with a 1.4.0b1 of October 2026) or `python-hl7` (BSD, stale since 2022) parse the full v2 grammar; the SS-MIX2 storage walker, MSH-18 decoding and the canonical-row mapping stay home-grown.
3. **Terminology** moves from curated parquet tables to the **OHDSI Standardized Vocabularies (Athena)** once OMOP is the core model. That brings a licence fact the owner must weigh now: **neither Japan nor Taiwan is a SNOMED International member** (verified on snomed.org today), so SNOMED CT use, which OMOP condition concepts require, needs an affiliate licence with an annual per-institution fee in both countries. None of MEDIS 標準病名, JLAC10, YJ, HOT or the Taiwan NHI codes is in Athena; they become TrialBox-maintained source vocabularies mapped through ICD-10, ATC and LOINC. Usagi (Apache-2.0) helps only through English concept names.
4. **The OHDSI tool chain is R-based** (Achilles, DataQualityDashboard, CohortDiagnostics, CirceR) and the design tools are Java (WhiteRabbit, Usagi, ATLAS/WebAPI). SqlRender supports both `postgresql` and `duckdb` (verified), and HADES lists both as supported platforms (verified), so the OMOP tables can be queried from either store. Shipping R and Java desktop tools inside an offline Windows/WSL2 appliance is a real cost (about 2 GB, a second runtime, no Japanese UI). The recommendation is to run them vendor-side or in a maintenance container, and to keep the box's runtime Python plus SQL.
5. **Vector and full-text search** should be pgvector (PostgreSQL licence, 0.8.7, Postgres 13+) and PGroonga (PostgreSQL licence, 4.0.4; bigram tokenizer handles Japanese and Chinese, MeCab optional) in the same Postgres 16. **ParadeDB `pg_search` is AGPL-3.0 and should not be bundled.** No LlamaIndex or Haystack: the retrieval the profile needs is a few hundred lines on top of the gateway's label and audit discipline, and both frameworks would pull in large dependency trees.
6. **Monitoring** is missing. Prometheus exposition from each FastAPI service plus a single-binary store with its own UI (VictoriaMetrics, Apache-2.0) fits one workstation. Grafana and Loki are AGPL-3.0: unmodified redistribution is permitted by Grafana Labs' own statements but needs the owner's legal review; the review recommends not bundling them at the pilot.
7. **Supply chain** needs the tools the spec already promises: `uv lock` with hashes, an SBOM (Syft, Apache-2.0, CycloneDX output), a vulnerability scan (Trivy, Apache-2.0) and a THIRD_PARTY_NOTICES file. Three runtime dependencies are LGPL (psycopg 3 is LGPL-3.0-only; py7zr and docxtpl are LGPL-2.1), which is compatible with a proprietary product when used unmodified as installed packages, but they must be listed. dulwich is dual Apache-2.0 / GPL-2+; take it under Apache-2.0 and say so. axe-core (MPL-2.0) and htmx 2.0.4 (0BSD) are vendored test assets.

Licences of the models the box serves were checked today: **Gemma 4 26B-A4B-it is Apache-2.0** on its Hugging Face card (the Gemma Terms of Use page explicitly excludes Gemma 4), **Qwen3.5-9B is Apache-2.0**, **bge-m3 is MIT**. vLLM 0.32.0 (pinned by the compose files) exists; 0.33.0 was released 2 November 2026. DuckDB 1.5.5 (pinned) exists; DuckDB 2.0.0 was released 21 October 2026, so the pin is deliberate and should stay until tested.

Counts over the 48 components inventoried: **keep 30, adopt a library or tool 15, replace 3** (the HL7 v2 parser, the hand-rolled encoding trial, the curated terminology tables as the primary source). The prioritised list is §6; the pilot-blocking ones are auth, supply chain, HL7 parsing, the DB pool and monitoring. OMOP, pgvector and PGroonga start now but the pilot can run on the current lake.

## 5. Where home-grown is the right call

Stated plainly, because the owner asked for honesty:

- **The eligibility engine** (IR, three-valued SQL, fail-closed families, equivalence gate). No open tool models "unknown because the code system is unreadable" or "proposed fact". Circe is two-valued. Keep it, and add Circe only as an exchange format and second oracle.
- **The gateway and two-model cascade.** The data-class policy, pinned builds, echo check, quote verification and canary gate are the product's safety case. LiteLLM would remove them.
- **The outbox.** Exactly-once mail with an `uncertain` state a person resolves, proven by kill-loop tests. Queue libraries do not give that.
- **SS-MIX2 storage, era and 民國 dates, JP/TW identifiers with check digits, the PHI scrubber.** Nothing in the ecosystem covers these; the fixes are consolidation and property tests, not libraries.
- **The audit chain, backup format and update path.** Simple, auditable, well tested; the gaps (schedule, off-box target, anti-rollback, Windows KEK) are design items.
- **The forms engine, ODM writer and REDCap client.** The simulator-backed tests are worth more than PyCap or odmlib would add; use odmlib as a test oracle only.
- **The console.** A no-script, CSP-locked Jinja2 app that passes axe and tap-count checks in three languages is the right shape for hospital staff; a SPA framework would cost accessibility and add a build chain.

Where home-grown is the wrong call: authentication (MFA, LDAP, OIDC), the HL7 v2 grammar, encoding detection, monitoring, and, once OMOP is the model, the terminology tables.
