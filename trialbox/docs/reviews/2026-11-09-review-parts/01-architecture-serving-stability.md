# TrialBox pre-release review 01: architecture, model serving and stability

Reviewer: Claude (Fable), independent. Head reviewed: `origin/master` ada9c8f (`/home/user/Auto-GPT/trialbox`). Read-only: no edits, no commits, no cloud resources. Commands run here are quoted in the evidence column; everything else is file:line.

## Summary

The architecture is sound and matches the eight documents in the large: one Postgres `trialbox_wf` for trial facts, DuckDB + HAPI for clinical facts, the gateway as the only model path, the two-model rule in one function, the canary as a gate, and a job engine whose recovery, idempotency keys and audit chain are better than most. Three things stand between it and a release on a real box.

1. **The production model path has never run and, as wired, cannot run.** Every PHI prompt (the judge, chart facts, consent drafts) is labelled D3 when `TB_DATA_CLASS` is unset, which is what `install.sh` and the wizard leave it as; the compose gateway is built without a step confirmer and refuses every D3 call unconditionally. Every GPU measurement so far attached the models directly, bypassing the gateway. On an installed box no note would ever be judged (A-01, Blocker).
2. **One lost connection takes a service down until a human restarts it.** Each store holds one psycopg connection for the life of the process and never reconnects; I measured it on a throwaway cluster (A-02). Docker's restart policy does not act on health, and the console's health check does not touch the database.
3. **The cloud-run wrapper and the stability of long runs rest on a local process surviving.** Today's incident is the design, not an accident: no cloud-side run limit, no on-VM self-shutdown, a best-effort trap, a wait loop that swallows auth failures (A-03). On the box the same pattern shows as a mail outage that leaves sends "uncertain" with no resolution path (A-04), no container memory limits on a host whose RAM budget is already spoken for (A-05), a SCREEN run that cannot be cancelled or short-circuited while the model hangs (A-08), and restart recovery that repeats every model call (A-09).

Model serving itself (profiles, sampling, the pair rule, the swap, the measured-record gate) is carefully done; the gaps are a token-budget bug that hides long notes (A-06), a strictly sequential S3 with a silent 2,000-pair budget at hospital scale (A-07), and a reproducibility claim the pair does not meet (A-10).

Counts: **Blocker 1, High 4, Medium 9, Low 8** (22 findings).

## What is good

- **Fail-closed by construction.** `tb_common.pair.combine` is the one two-model rule; a verifier that is down, disagrees or cannot quote gives `unknown`, never an exclusion; the canary gate (`effective_note_block`) falls back to "review, never out" when stale, failed or after a bad wake check; `check_failures` fails a run whose model was down rather than shipping a filters-only list; a lake query error (not a missing table) stops the run instead of skipping opt-outs (D-127 F-04).
- **Serving discipline.** Forced sampling (`temperature 0, top_p 1, seed`), schema-constrained output with one retry, served-model echo check against the pinned build, a measured-record gate before a tier may install, images pinned by digest, `--limit-mm-per-prompt` closing the multimodal surface, the verifier started only after the judge is healthy so vLLM's free-memory check holds.
- **The swap.** Hold-and-release with a lapse, lazy swaps, a wake check per real swap, on-demand wake for chat, `model_busy` within 30 s for a person; measured on the capped card with answers after a wake equal to resident.
- **Job engine.** `FOR UPDATE SKIP LOCKED` claims, restart recovery of interrupted jobs, run date fixed at start, idempotent job creation on a pre-allocated id, per-sender rate limit, `misfire_grace_time` 6 h with coalescing, idempotency keys on every mail including the daily notice key.
- **Audit.** Torn-line repair kept as evidence, free-space check before each write, `flock` across containers, file order kept under clock jumps, `fsync` per line.
- **Lake.** Read-only connections, SELECT-only guard, memory cap and spill directory, per-query interrupt timer, configuration locked.
- **Cloud wrapper hygiene.** Private `CLOUDSDK_CONFIG` enforced, the key made fresh per run into a 0600 file and never printed by `gpu-pro6000-run.sh`, the live serving record checked before spending, `--dry-run` for the whole sequence, `--stop` by hand.
- **Documents match the code** in structure and boundaries (services, networks, data path, stores); the mismatches found are the outbox (A-13) and the byte-identical claim (A-10).
