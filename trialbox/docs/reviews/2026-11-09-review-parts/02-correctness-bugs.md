# TrialBox pre-release review 02 — correctness bugs in the core code paths

Reviewed: `/home/user/Auto-GPT/trialbox` at `ada9c8f` (origin/master), read-only, 2026-11-09.
Scratch scripts and reproductions: `/tmp/claude-0/review-2026-11-09/scratch-02/` (`repro_lake.py`,
`repro_lifecycle_anchors.py`, `repro_sync_blank.py`; the encoding and messy-data snippets were run inline).

## Summary

18 proven defects: **1 Blocker, 2 High, 8 Medium, 7 Low**, plus 9 suspected items that need data or a spec the repo
does not hold.

The two-model rule itself holds: a note criterion excludes only when `tb_common.pair.combine` sees judge and verifier
agree (quote verified on both sides, min confidence, `MIN_CONFIDENCE` floor), a single model or a failed canary makes
every note `fail` soft (`effective_note_block`), garbled model output is rejected by the strict JSON schema and becomes
`model_down` → unknown, and the S4 second opinion can only turn a strong candidate into `unknown`. The engine-level
problems are elsewhere:

* **B-01 (Blocker).** The compiled SQL turns an observation whose value is not numeric (text result, flagged result,
  "<0.3", `valueString` from SS-MIX2 OBX-5) into **FALSE**, not NULL. Under v1 semantics, and for every value criterion
  under affirmative semantics, that is a hard exclusion in both runtime paths. This is exactly the class D-130 closed for
  diagnoses and medicines, left open for labs. Reproduced.
* **B-02 (High).** In the SCREEN cascade a scoped patient the SQL `base` CTE drops (not in `patient` on the pinned
  snapshot, a `deceased_date`, a `birth_date` after the run date) gets `in_scope=False` and the list tier **excluded**,
  while the v1 path (and D-118) say *review*. The `not_in_snapshot` fallback in `screen_with_cascade` is dead code.
  Reproduced.
* **B-03 (High).** REDCap sync on a longitudinal project with no `event` configured takes the blank cells of every
  other event as changes and **blanks TrialBox's value at the end of every sync**, so `derive` never sees the
  enrolment/consent dates and the lifecycle does not move. Reproduced.
* Data-integrity defects in the lifecycle (`undo` does not remove the visit anchor), backup (hashes and row counts
  taken outside the dump → a live-box backup refuses to restore), update (a failed rollback point leaves the box
  stopped while reporting "nothing was changed"), encodings (Big5 sheets decoded as Shift_JIS; dictionary upload with
  `errors="replace"`), SS-MIX2 lab units (OBX-6 ignored), and pseudonym joins (leading zeros).

Severity scale: Blocker = a patient can be wrongly dropped silently or trial data silently corrupted on a normal path;
High = same, on a less common but realistic path; Medium = wrong result or operator misled, usually visible; Low =
edge case or cosmetic/consistency.

## Suspected, not proven

1. **SS-MIX2 疑い (suspected) diagnoses ingested as active conditions** — `adapter/sources/ssmix2/source.py:_diagnosis` reads PRB-3/4/14/16 only. JAHIS's 病名情報データ交換規約 carries the 疑いフラグ (suspected flag) in PRB-13 (problem confirmation status); nothing in the reader or the JP Core mapping reads it, so "肺癌の疑い" becomes a coded malignancy and an exclusion criterion drops the patient (the judge prompt was tuned for this in notes, `docs/DECISIONS.md:809-813`, but the coded path has no such rule). Needs the SS-MIX2 spec/sample messages to confirm the field. Potentially High.
2. **MEDIS `ICD10-2013` codes without a dot** — `_icd()` accepts a licensed target only if `code in self._cm`, and `icd10cm_full.parquet` holds dotted codes (`A00.0`); the unit test uses dotted `M10.9`. If the real MEDIS release prints `M109` (as the レセ電 masters do), every licensed lookup falls to `byomei_to_icd10.csv` and the licensed file is useless (patients stay unknown — safe, but the D-137 feature does nothing). Normalise by inserting the dot after the third character.
3. **`hl7.decode` aborts the whole read** on a Shift_JIS file or ISO-2022-JP with JIS X 0212 / NEC gaiji (`iso2022_jp` codec lacks them): `UnicodeDecodeError` propagates from `_messages()` and nothing catches it per file. Needs vendor samples.
4. **D-130 covers only condition/medication.** Under v1 semantics a FALSE presence atom on `procedure`, `encounter` (department ValueSet), `report`, `observation`-presence or a `medication` duration with a local/unmapped code is still a hard exclusion (`Coverage.DOMAINS = ("condition","medication")`). Same mechanism as B-01; not reproduced with a fixture.
5. **CJK token estimate** (`evaluate._tokens`, `judge.expected_tokens`) counts only U+3000–U+9FFF (+ compat in one of them); Hangul, full-width forms (U+FF00–FFEF) and half-width katakana count as Latin/4. Excerpt budgets can overshoot the 2,500-token promise on JP notes with full-width digits.
6. **HbA1c JDS vs NGSP** (Japanese values before 2012-04 are 0.4 lower): same `%` unit, no conversion; only matters for historical windows.
7. **`Coverage` over-reports medicines**: rows with an NHI code but no ATC count as unreadable although medication ValueSets also match `nhi_drug` codes (`generator.PRESENCE`) — noise (more unknowns), not a wrong exclusion.
8. **Lake LIKE escaping** in `refdata.ctgov_search` relies on PostgreSQL's default backslash escape — correct on Postgres (confirmed `tb_common/db.py` is psycopg), would break on another engine.
9. **`find_header`** takes a two-cell title row ("Patient list", "Dr. Tanaka") as the header (both are "words"); the real header then becomes a data row and is usually caught by the `chart_column` check, not silently — not reproduced on a real sheet.

## Checked and found sound (for the record)

* Two-model rule: `pair.combine`, `needs_verifier`, `floor`; `NoteJudge.judge_excerpts`; `OrchestratorJudge` S3 via the same path; `two_phase` rounds (deferred verifier answers are replaced by real ones, strict last round → `model_down`); `check_judge` 10 % rule; `effective_note_block` falls back to `never` without a verifier or canary; judge output schema is strict (`verdict` enum, `confidence` 0–1), so garbled output → `LlmSchemaError` → unknown.
* D-130 unknown-code-system path in both engines; D-135 proposed-fact rule (`Proposed.refs`, signed atoms) never decides, only widens to unknown; `_off` three-valued CTE.
* Lifecycle state machine (`NEXT`, `can_step`, optimistic `_move`, `undo` bookkeeping via `live_steps`), `visit_status` window maths, `worklist`; orchestrator clock is the site zone (`app.py:373`), console `today` is `local_today(site_zone)`.
* Branching parser/evaluator, `save_form` hidden/required rules, forms `problem()` validation, ODM/CSV export structure.
* Refdata pack: manifest checks, tar member filtering + `extractall(filter="data")`, sha/size/record verification, one-transaction load.
* Backup crypto: fresh X25519 ephemeral key per backup, HKDF, AES-GCM with counter nonces, header in AAD, last-chunk flag, truncation/reorder refused; `unpack` uses `filter="data"`.
* Console auth: scrypt, constant-work login, lockout, server-side sessions with idle/absolute limits, CSRF compare_digest; `/api/v1` routes share `study_or_404` + `need_change` with the pages; N1/N2 show the screening number beside the pseudonym (D-136) and use one UTC clock for marks and digest cut-offs.
