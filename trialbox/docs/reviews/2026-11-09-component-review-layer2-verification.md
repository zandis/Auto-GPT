## 1. Summary

Layer 1's broad shape holds: the home-grown core (eligibility engine, gateway, cascade, PHI recognisers, SS-MIX2 storage walker, dates, audit chain, backup and update path, console, forms, REDCap client) is the right call, and the five "adopt" moves that matter for a pilot (identity provider, supply chain, DB pool, monitoring, one OCR module) are right in direction. Of the twelve headline recommendations I **confirm 6, confirm 3 with material corrections, correct 3 and reject none**; two layer-1 "unverified" items are now settled (OHDSI CommonDataModel is Apache-2.0; Authelia has `ja-JP` and `zh-TW` locales and an `activedirectory` LDAP implementation).

The corrections that change what gets built:

1. **hl7apy is the wrong library for SS-MIX2.** Measured today on one PPR-01 message: hl7apy (tolerant, no groups) 166 messages/s; python-hl7 3,817/s; the home-grown parser 345,000/s. A 50,000-patient SS-MIX2 storage holds millions of files, so hl7apy turns a minutes-long ingest into hours. hl7apy also leaves the sub-components of a Z-segment field unparsed in tolerant mode (`疑い&flag` came back raw), which is exactly the field class R-08 needs. python-hl7 (BSD-3, 0.4.5 of March 2022, stale but complete) parsed MSH-2 custom delimiters, repetitions, sub-components and escapes correctly in the same test; the home-grown parser returned `''` for PRB-3.4 when MSH-2 used `#` as the component separator and did not split `&`. **Use python-hl7 behind the existing `Segment`/`Message` API, or fix the 92-line parser (about 60 lines: read MSH-2, split `&`, keep repetitions) with hypothesis round-trips.** R-66 of the full review had already named python-hl7; layer 1 overrode it without a benchmark.
2. **The Postgres image must change before any real data exists.** The compose file pins `postgres:16-alpine` by digest. pgvector ships Debian images only (`pg16-bookworm`, `pg16-trixie`, no alpine tag); PGroonga's Debian packages are for **trixie** only and its Docker images come in `debian-16` and `alpine-16`; Alpine's own `postgresql-pgvector` is 0.8.1 on `edge` community. Any workable combination moves the cluster from musl to glibc, which changes text collation and requires a REINDEX of every text index (PostgreSQL wiki "Locale data changes": "a query could fail to find data that is actually there"). This is a one-day change now and a migration later. Layer 1 put pgvector/PGroonga at rank 10 ("with the profile work"); the **image decision moves to the pre-pilot list**, the retrieval code can stay at rank 10. Also: PGroonga's current release is **4.1.0 (2026-10-09)**, not 4.0.4.
3. **PaddleOCR: the current code does not run on PaddleOCR 3.x, and the 5090 cannot run it on the GPU.** `doc_parser._ocr_pdf` uses the 2.x API (`show_log=`, `.ocr(..., cls=False)`); 3.x uses `.predict()` and deprecates `use_angle_cls`. PaddleOCR 3.7.0 (June 2026) defaults to **PP-OCRv6_medium**, so `ocr_version="PP-OCRv5"` must be pinned (or v6 evaluated). PP-OCRv5's one recognition model covers Simplified Chinese, Traditional Chinese, Pinyin, English and Japanese (confirmed), so the per-site `lang` switch layer 1 proposed is unnecessary under v5. PaddlePaddle GPU wheels (cu118, cu126) come from a vendor index, not PyPI, and the vendor's own page says standard wheels "don't work properly" on 50-series cards (the RTX 5090 tier) and offers only a development build. **Run OCR CPU-only in the doc-parser/sitesetup image** (server rec model 81 MB, ~31 ms per text line on CPU); the GPU is 0.81 allocated to vLLM anyway. For Japanese paper charts, **NDLOCR-Lite** (National Diet Library, CC BY 4.0, CPU, vertical text) is a missed candidate.
4. **Licence inventory: eight LGPL packages, not three.** The lock scan found `psycopg`, `psycopg-binary` (LGPL-3.0-only), `py7zr`, `pybcj`, `pyppmd` (LGPL-2.1-or-later), `inflate64`, `multivolumefile` (LGPLv2+) and `docxtpl` (LGPL-2.1-only), plus `certifi` (MPL-2.0) and `dulwich` (Apache-2.0 OR GPL-2.0-or-later). All are compatible with a proprietary product used unmodified as installed packages, and five of the eight disappear if R-12 (links instead of 7z attachments) is implemented. The NOTICE file must list all of them.
5. **Authelia's OIDC provider is OpenID Certified but formally beta** (Beta 8 in progress for v4.40; Beta 9, which holds RP-initiated and back-channel logout, not started). Fit is still good for one box: LDAP/AD backend with an `activedirectory` implementation, `ja-JP` and `zh-TW` locales, Postgres storage, in-memory sessions for one instance, TLS a strict requirement. Consequences layer 1 did not state: the console's sign-out must redirect to Authelia's own logout endpoint; the portal needs a hospital DNS name and certificate (not `127.0.0.1`; WebAuthn and the Secure cookie need a secure origin on the LAN). Keycloak 26.8.2 (5 Nov 2026) has `ja` and `zh_Hant` message bundles and complete logout flows, but its documented base is 1,250 MB RAM, which argues for Authelia on the 64 GB 5090 box.
6. **SNOMED has a price now, not a question.** Japan and Taiwan are not members (confirmed on snomed.org today). SNOMED International's fee page: affiliate use in a non-member territory costs **USD 1,954 per Data Processing System per year** for a hospital in a World Bank high-income territory (both countries), with registration before use and an annual Statement of Usage via MLDS. The design document's recommended answer (`*_concept_id = 0`, source concepts filled) avoids the fee and is right for screening, but the CDM is then non-standard for Achilles, DQD and any OHDSI network study; that trade must be written down as a decision, not left as "ask".
7. **Two "keep" items are unused code.** `services/dataplat/` (3,146 lines) is imported by no service, only by `tools/` (eval, testbench, cascade_e2e). `orchestrator.outbox.Dispatcher` is instantiated nowhere outside its own module (R-16 says the same). "Keep" for these means "wire it or delete it", not "leave it".

Everything else in layer 1 checks out, including the licence facts for Gemma 4 (Apache-2.0 on the card; the Gemma Terms page excludes Gemma 4 and links a separate licence file whose text I did not read: counsel should), Qwen3.5-9B (Apache-2.0), ParadeDB (AGPL-3.0 since inception, commercial licence available), YomiToku (CC BY-NC-SA, paid PoCs count as commercial), vLLM 0.32.0/0.33.0 and DuckDB 1.5.5/1.5.6/2.0.0 dates, JP Core 1.2.0 and TW Core 1.0.0, Trivy's air-gap mode, uv's hashes, VictoriaMetrics Apache-2.0, pgBackRest 2.60.0 MIT, procrastinate 3.10.0 MIT, Authlib 1.9.5 BSD-3, docling 2.149.0 MIT.

- **LGPL (8 packages).** Used unmodified as separately installed Python packages inside Docker images that TrialBox distributes to hospitals. ## 7. Sequencing for a first pilot

Layer 1's order (auth, supply chain, HL7, pool, monitoring, OCR, encodings, IG versions, OMOP, pgvector/PGroonga, profile, Circe/DQD, pgBackRest, CI, hygiene) is mostly right. Three changes: the **Postgres image decision moves to the front** (it is a one-day change now and a REINDEX migration later), **supply chain goes before auth** (it is small, it blocks every bundle anyone installs, and R-19's pypdf/pillow advisories sit on the mailed-protocol path), and **auth starts its hospital-IT dependency (hostname, certificate, AD service account) at once** because that lead time, not the code, decides the date. Wave 1 of the full review (patient-safety and correctness fixes, Gate G1) precedes all of this except the pool.
