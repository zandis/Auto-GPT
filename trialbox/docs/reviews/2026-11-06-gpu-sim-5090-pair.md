# 5090-like run of the consumer-GPU pair on a real card (2026-11-06)

Follow-up to `2026-11-05-consumer-gpu-filter-first.md`. That doc measured the pair on OpenRouter fp4 providers and said only the exact 4-bit files on the exact engine settle it. This run does that.

## Setup

- GCP `g4-standard-48` Spot in asia-east1-a: one RTX PRO 6000 (96 GB, same Blackwell GB202 chip and memory speed as an RTX 5090), driver 580, vLLM v0.32.0.
- Judge: `nvidia/Gemma-4-26B-A4B-NVFP4`. Verifier: `cyankiwi/Qwen3.5-9B-AWQ-4bit`, thinking off. Both resident together, each capped with `--gpu-memory-utilization` (0.22 and 0.105), 8k context, 4 sequences, eager mode.
- Data: the 1,015 physician-labelled SIGIR criteria (79 eligible patient x trial pairs), English and machine-translated Japanese notes, `python -m tools.trialgpt_compare run --pipelines trialbox`, then `filterfirst` (assumes perfect structured filters, as before).
- Scripts: `deploy/gcp/gpu-sim-startup.sh` (VM startup), `deploy/gcp/setup-gcp.sh` (one-time project setup).

## Results (filter first, eligible pairs lost of 79; block recall)

| setup | en lost | ja lost | block recall en / ja |
| --- | --- | --- | --- |
| **On-card pair: Gemma NVFP4 + Qwen AWQ, both must block** | **4** | **3** | 0.52 / 0.48 |
| Same pair via OpenRouter fp4 providers (5 Nov) | 1 | 2 | 0.58 / 0.58 |
| Spark pair today (gpt-oss-120b + Gemma 4) | 5 | 4 | – |
| Gemma NVFP4 alone (on card) | 11 | 12 | 0.76 / 0.70 |
| Gemma fp4 alone (OpenRouter) | 5 | 5 | 0.67 / 0.73 |
| Qwen AWQ alone (on card) | 4 | 5 | 0.52 / 0.48 |
| Qwen3.5-9B alone (OpenRouter) | 3 | 2 | 0.64 / 0.58 |

Valid answers: 4,059 of 4,060 (one empty Qwen answer, counted as abstain).

## What it means

- The pair on the real files is still at least as safe as today's Spark pair (4/3 vs 5/4 lost), but not as good as the OpenRouter estimate (1/2). The 1/2 figure should not be quoted as a 5090 result.
- The NVIDIA NVFP4 Gemma file blocks much more readily than the OpenRouter fp4 provider (11 vs 5 lost alone). The two-model agreement rule absorbs most of that. Another 4-bit Gemma build (AWQ, QAT) is worth one more run.
- **Memory: the pair did not fit 32 GB as configured.** Weights alone load at 17.1 GiB (Gemma) + 7.5 GiB (Qwen); with KV cache and CUDA overhead the card showed 35.0 GiB used. At the compose's original caps (0.60/0.28 of 32 GB) the judge failed to start. Getting under 32 GB needs a shorter context (4k), fewer sequences, or a smaller verifier build; not yet tested. Update `docker-compose.rtx5090.yml` estimates after that test.
- Speed: 4,060 criterion checks in 14 minutes with 4 concurrent requests per model (about 4.8 checks per second for the pair).

## Limits

79 eligible pairs is a small set; one pair is 1.3 points. Japanese notes are machine-translated. Filters are assumed perfect. The RTX PRO 6000 has the same chip as a 5090 but more memory and a datacenter driver; speed on a real 5090 may differ slightly.
