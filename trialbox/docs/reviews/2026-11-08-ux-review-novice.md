# TrialBox console: UI/UX review for novice hospital users (ja, zh-TW, en)

Date: 2026-11-08. Build reviewed: `trialbox/services/console` on the public-data site served by `tools.public_e2e --serve` (port 8097).
Personas: a research nurse / CRC with little IT skill; a busy PI reading on a phone between clinics; an admin who is a hospital IT generalist.

How this was checked. 696 page loads with Playwright (5 roles x 3 languages x desktop 1280 px and phone 390 px, every page each role can reach, plus sign-in, failed sign-in, 403 and 404). Screenshots are in `/tmp/claude-0/-home-user-Auto-GPT/b6dc012b-d091-5e78-8158-ebd09d964152/scratchpad/ux-shots/` (969 files; names are `<role>-<lang>-<view>-<page>.png`, `full-...` for full-page, `task-...` for the task flows). Metrics per page (touch-target sizes, font sizes, page height, overflow, axe-core 4.10 violations) are in `walk-metrics.json`; the task flows with tap counts are in `task-metrics-*.json`. Templates (`services/console/templates/*.html`) and all six catalogues (`i18n*.py`) were read for the wording.

Legend: **[seen]** = verified on screen or in the HTTP response; **[code]** = inferred from the templates or catalogue text; **[both]** = seen on screen and confirmed in code.

## 1. Verdict

| Area | Score (1-5) | One line |
|---|---|---|
| Comprehension | **2** | Core clinic screens use plain words, but the product still speaks in its own vocabulary (ruleset, FEAS/SCREEN/CASE, S0-S5, D0, tier, pseudonym, orchestrator, lake, SHA-256, small-cell limit) and leaves study data labels in English on ja/zh-TW pages. |
| Guidance | **2** | The "Next:" line on the study card is good. Everywhere else the next step is not told: set-up has three Save buttons and a hidden dependency chain (token -> forms -> source), empty states say "none yet" without a button, error pages give one word, help is a generic paragraph with examples for a study the user does not have. |
| Effort | **3** | Marking a patient is two taps once signed in (good). But on a phone the chart panel opens eight screens below the row that was tapped, the CRC home starts with 25 clinic visits before the study cards, set-up has 28 inputs across 8 forms, and the audit page is 130 screens long. |
| Safety | **2** | A chart number (MRN) is printed in plain text on the CASE job page for every role that can open a job, including the PI and the viewer, with no reveal step and no audit. "Not suitable" with no reason chosen silently records "other illness". The one-time password of a new account travels in the URL. Unsaved edits in one set-up section are lost when another section is saved. No confirmation on Sign out, Detach, Keep-value, Disable, or start-a-job. |
| Accessibility | **2** | Every interactive element is under 44 px (nav 35 px, buttons 36 px, small buttons 28 px). Most text on screen is 12-13 px hint text. On a phone, job ids, timestamps and criteria text wrap one character per line. axe: scrollable tables not keyboard reachable (serious), no landmarks for header/banner, error pages have no heading. CJK line breaking is otherwise correct and no page scrolls sideways. |
| Consistency | **3** | One mark vocabulary is kept across screens (good). But the same thing has several names: box/装置/箱/機器/本機, role/ロール/役割, sponsor/依頼者/贊助者/委託者, patient/患者/患者さん, Sign in/サインイン vs the hospital's ログイン; nav labels differ by role for the same page (My patients / This week / 担当患者 / 今週の候補患者リスト). |
| Trust | **3** | The "Why this patient fits" line, the per-criterion verdict with a quote and date, and the "reading aid; the investigator decides" footer are the best parts of the product. But every patient on the list shows the same "4/7, 2 unknown, to review", confidence is never explained, "First check / Second check" is unexplained, and the model's role is written only for admins. |

Overall: **2.5 / 5 for a novice.** The clinic core (week list, patient page, marks, outcomes) is close; the surrounding product (set-up, REDCap, data core, jobs, admin, errors, help) is written for the builder.

## 5. Patterns to add

1. **Study set-up wizard (CRC).** One flow with a progress bar: 1 Study basics (type, consent) -> 2 Numbering (prefix shown as a live example "PUB-ONC-0001", reasons list) -> 3 REDCap (optional; token test -> project -> field pickers from the dictionary read over the API) -> 4 Review and save. One Save, state kept across steps, "You can come back any time". Replaces the three forms on `/setup`, the CSV import on `/forms` and the field-map textarea on `/sources` for the common case.
2. **First-run wizard (every role).** After the first sign-in: 1 Change your password (enforced), 2 Choose language and mail language, 3 "Here is your home and the one thing to do next" with a 20-second tour. Admin variant: 1 add the REDCap key, 2 create the CRC and PI accounts, 3 check health.
3. **Empty states that teach.** Every empty list shows: what will appear here, what makes it appear, and one button. Examples: week list "No screening run yet. The CRC starts it from Study set-up. [Ask the CRC]"; conflicts "Nothing to resolve. Values appear here after a sync when TrialBox and REDCap disagree"; registry "Nobody approached yet. A number is given when the investigator marks OK to contact"; reports "No report yet: [Count eligible patients] takes about 5 minutes". The study card for a new study: "Step 1 of 6: upload the protocol [Upload]".
4. **Inline help ("?" on the thing, not the page).** A `<details>` or popover per heading and per odd term: "Why this patient fits (?)", "Criteria met 4/7 (?)", "Still needed (?)", "Reading GO (?)", "Look-back (?)". Text comes from the glossary above. The page-level Help keeps a 3-step "how to do this page" with a screenshot per language.
5. **Assistant entry point.** Keep the header field but make it an honest assistant: one box labelled "Ask TrialBox" that (a) routes codes and ids as today, (b) answers "where is / how do I" questions from the help text in the user's language with a link ("Where do I change my password?" -> /account#password), and (c) for anything that would run a job, proposes the exact action with a confirm page (the `/pilot/propose` flow already exists). On a phone it is the only header control besides the menu.
6. **Confirmations for risky actions.** Modal/sheet with the consequence in one sentence and a primary verb: Not suitable (reason required), Start a run (time and who gets mail), Detach REDCap, Keep/Take a value, Disable account, Reset password, Sign out when a form has edits, Approve all, Release consent pages, Show chart number (keep the reason, add "This is recorded with your name" on the button itself).
7. **Undo.** Toast with "Undo" for 10 seconds after a mark, an outcome, a conflict decision and a registry status change; "Withdraw my mark" already exists and should appear in the toast too. Keep an "Unsaved changes" guard on set-up and feasibility forms.
8. **Phone layout for the clinic core.** Patient sheet (full screen) with Back / Next patient; sticky mark bar at the bottom with 48 px buttons; rail lists as a horizontal chip row (exists) but with one merged "Needs a look" list; practitioner on one line.
9. **One name per page, one vocabulary per role.** A `nav.*`/`title` audit so tab = title = H1 = help heading, and a 30-term glossary enforced by a test on the catalogues (no 箱/装置/ジョブ/規則集 outside admin pages).
10. **Trust line on every patient.** "How sure: {met}/{total} from coded records · {n} read from notes by the AI (two readings agree) · {m} a person must check. The AI only suggests; you decide." Shown above the mark buttons, same words on the list row, the sheet and the full page.
