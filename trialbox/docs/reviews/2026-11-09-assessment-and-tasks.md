## 3. Task cards for parallel agents

### 3.0 How to read a card, and the rules every card carries

Each card: **ID and title**; **WS** (TB-PLAN-05 item) and **Trace** (URS, RSK, TST ids from the plan's §5, §6, §8); **Goal**; **Read first**; **May touch** (files and directories the task may change) and **Must not touch**; **Contract** (the interface it keeps or creates); **Acceptance** (measurable, with the command that shows it); **Tests to add** (positive and negative); **Depends on**; **Size** (S ≈ half a session, M ≈ one session, L ≈ two to three sessions, one reviewed pull request each); **Decisions** (the D-numbers reserved for it; use no other); **Review**.

Rules that apply to every card and are not repeated: (1) the branch is `agent/<task-id>-<slug>` from `origin/master` at the start of the task's wave; (2) the decision entry is written as `docs/decisions/D-<nnn>-<slug>.md` once T-002 has landed, and as the last entry of `docs/DECISIONS.md` only if T-002 has not (then the integrator moves it); (3) no card edits `docs/plan/25-master-plan.md` or `25-traceability.csv`; plan changes are listed in the pull request under "Plan changes requested" and made by the integrator in a plan pull request (v1.3); (4) `make lint` and `make test` green on the branch rebased on master, run with `--basetemp` under the scratchpad and `TB_TEST_PG_DIR` private to the branch (T-003); (5) synthetic data only, never a site sample (TB-SITE-03); (6) safety-core files (`services/orchestrator/scenarios/screen.py`, the cascade, the SQL generator `services/criteria_compiler/`, `libs/tb_common/audit.py`, `services/adapter/pidmap.py`, `libs/tb_common/labvalue.py`, `libs/tb_common/authz.py`, `services/console/auth.py`, `services/edc/`) take a Fable adversarial review before merge, whoever else reviews; (7) a card that must touch a file listed under "Must not touch" stops and asks the integrator; (8) RUNBOOK edits are confined to the section the card names.

## 5. Process fixes so parallel work stays safe

### 5.1 Decision numbers

Today: numbers are guessed at branch time and renumbered at merge (three times on 2026-11-09), and every branch conflicts on one file (P-11, P-31). The fix (T-002, this week):

1. **One file per decision** under `docs/decisions/D-<nnn>-<slug>.md`; `docs/DECISIONS.md` keeps its hand-written body up to the last entry merged today and gains a generated index below a marker. Two branches adding two files never conflict.
2. **The number comes from this document's card** (the "Decisions" field) and is confirmed by a one-line `reserved` row in `docs/decisions/REGISTRY.md`, merged by the integrator within the hour of a task's start. The registry is the only file that can conflict, and its conflicts are one-line and mechanical.
3. **Never renumber after a pull request is opened.** A clash found at merge is resolved by the later branch taking the next free number in its own range; cross-references use the id, so the change is one search-and-replace in that branch only.
4. **Gaps are allowed and recorded** (`unused` rows): D-152 to D-159 and D-164 to D-169 today.
5. **A doclint check** fails CI on a duplicate number, a number outside the card's range, or a decision file whose header does not name its task id and pull request.
6. **Owner decisions** go into a decision file the same day (P-40): the reviews file stays a narrative; the D-entry is the controlled record (PR-34).
7. Ranges: this document allocates D-190 to D-269 by wave; the sibling keeps D-170 to D-189; the integrator allocates from D-270 for new cards.

### 5.2 Test isolation

1. **One temp root per branch** (`TB_TEST_ROOT`, default under the scratchpad), the Postgres cluster under it with an owner pid file and `atexit` stop; `python -m tools.pglocal --gc` reaps orphans (T-003). No fixed `/tmp/tb-*` path anywhere; a lint test greps for it.
2. **One venv per branch**, built by `uv sync --frozen --group test` from the committed `uv.lock`; no `pip install` into a venv another agent runs; `make venv` recreates, never mutates. The plugin set is the lock's; `addopts` carries `-p no:randomly -p no:cacheprovider`.
3. **Random order is a nightly job, not a default**: the sibling's order-independence work runs `pytest -p randomly --randomly-seed=<date>` nightly in CI and reports the seed; an agent who wants it locally sets `TB_TEST_RANDOM=1`, which removes the `-p no:randomly` line for that run and prints the seed.
4. **`pytest-xdist` by default** (`-n auto`, per-worker `tb_prefix` already supports it); the 18-minute serial suite becomes about 6 to 8 minutes; CI runs the same.
5. **Append-only registration files** become per-feature files: `tests/unit/test_no_direct_model_calls.py`'s allowlist moves to `tests/allow/direct_model_calls/<feature>.txt` (one file per feature, globbed), `tools/e2e_simple.py`'s stage list reads `tools/e2e_stages/*.py` (one file per stage, ordered by number), `tests/unit/test_gateway_box_phi.py` keeps its cases in `tests/fixtures/gateway_cases/*.yaml`. A card adds a file, never a line in a shared list (part of T-007 or a new S card at the integrator's call).
6. **Stubs that cannot hide the bug**: the in-process stub serves exactly one `model` name (the configured served name) and answers 404 to any other; `/v1/models` lists it (closes P-34a); a stub mode `note_block: planted` lets a scenario plant one exclusion so the engines' exclusion path is exercised under CI (closes R-15's "can never exclude"); a fake record source (`FakeFacts`) is allowed only beside a lake-backed test of the same rule (E-24). These three are a wave-1 S card (T-120, D-217) the integrator opens.
7. **Goldens are the merge gate for every data-core branch** (T-006, holistic C-17): identical or the pull request explains the change and regenerates in the same commit.

### 5.3 Disk hygiene

1. **`make clean-tmp` before every suite run** in an agent's loop, and `make check-disk` (≥ 20 GB free) as the first step of every card; today the machine has 3 GB free and will fail the next rehearsal or test run on ENOSPC (P-50).
2. **Run artefacts leave the repository tree**: `.cache/complete-run/` moves to `$TB_RUNS_DIR` (default `<scratchpad>/tb-runs`); only `report.md`, `report.json`, the serving record and the bench results are copied into `docs/plan/measurements/<run>/`; `src.tgz` and `results.tgz` are kept for the two newest runs (T-003, T-004).
3. **Retention rules for the temp roots**: pytest `tmp_path_retention_count = 1`, `policy = failed`; the rehearsal's `evidence/` keeps the newest two cases per name and deletes `runs/` and `base.tgz` on exit (its trap does today; `evidence/` grows unbounded); the backup and update drills write under `TB_TEST_ROOT`.
4. **A weekly `make clean-tmp` scheduled task** on shared machines, and a size budget per agent (10 GB under its `TB_TEST_ROOT`) that the `check-disk` step reports.
5. The `.cache/` entries that are inputs (`jvm` 768 MB, `refdata` 335 MB, `trec_ct` 429 MB, `medtxt`, `fonts`) stay; `refdata-research` (570 MB) is the sibling's and should move out of the repository tree when their work merges.

### 5.4 The rehearsal gates

1. **No paid launch without `REHEARSAL PASSED` on the exact commit** (D-150, RUNBOOK §11): the launch record (T-004) carries the rehearsal evidence's sha and the commit; a run from a commit that did not pass is a process deviation recorded in the release record.
2. **The rehearsal in CI**: `make rehearse CASES=run-a` (about 20 minutes) as a required check on every pull request that touches `deploy/gcp/*`, `tools/complete_run.py`, `tools/scenarios.py`, `tools/fetch_run_data.py` or `tests/rehearsal/*` (paths filter); the full six cases nightly. Needs a runner with docker and 4 GB; until one exists, the integrator runs it locally and attaches the evidence sha to the pull request.
3. **Bounded first, full second**: every new VM script or profile (`b200-qualify.sh`, the Spark, the platform) gets a rehearsal case before its first paid boot, and its first paid boot is `--only` two or three parts with `--hours ≤ 3`.
4. **Negative cases are part of the gate**: a rehearsal that passes only `run-a` is not a pass; `served`, `no-upload`, `hang`, `busy`, `run-b` (and `bucket`, `b200` when added) must each fail or pass as their `check.py` says.
5. **The quota and the cap are read before every start**, never assumed (D-150 does this; the launch record shows the read-out); `--vms N > 1` stays refused until the owner's quota increase is granted and recorded.
6. **Model quality is not rehearsed**: the rehearsal proves plumbing; G1's model-layer acceptance (false exclusions 0, precision ≥ 0.90, recall ≥ 0.70, canary) is judged from the paid run's report by a human and a Fable read, never inferred from a green rehearsal.

1. **One integrator role per day** (an agent session with no feature card): merges to `origin/master` one at a time, rebases the next branch, runs `make ci` on the result, resolves only the three by-rule files (§4.5), and updates `REGISTRY.md` and the plan (v1.3 changes collected from the cards' "Plan changes requested").

4. **Plan edits only in plan pull requests** with a version bump and a change-history row (P-18); a feature pull request lists what it needs changed.
5. **Every pull request names its card id, its D-number, its change class (CC1 to CC6), its reviewer and the review hours** (the PR template of T-215; until then in the description), so the GAMP record is built as the work happens, not reconstructed.
