データを院外に出さずに、治験に必要な患者を見つける。

TrialBox は病院内で動く適格性コンパイラ兼患者探索アプライアンスです。治験プロトコル、台湾の健保給付規定、 コホート定義を、病院自身の診療記録に対する監査可能な患者スクリーニングに変換し、実施可能性の問い合わせにメールまたは管理コンソールから回答します。

3 つの原則

データは院外に出ない

院内ネットワークの DGX Spark または任意の Docker ホストで動作します。モデルはボックス上で提供され、 外向き通信は既定で遮断。治験依頼者に渡るのは、小セルを秘匿した集計レポートだけです。

エージェントが起案し、エンジンが判定する

言語モデルの役割は、文書から基準を抽出することと、構造化データでは答えられない部分について自由記載を読むことだけ。 すべての件数は、レビュー済みルールセットから生成された決定論的 SQL（CQL と照合済み）で算出します。

人が承認する

コンパイルされたルールセットはコーディネーターがレビュー用ワークブックで承認し、適格性は治験責任医師が判断します。 すべてのリクエスト、モデル呼び出し、出力ファイルは追記専用の監査証跡にハッシュで記録されます。

仕組み

{{pipeline_ja}}

カスケードは安価で厳密な段階から実行します。SQL（S0–S1）がモデル費用ゼロで大半の患者を除外し、 辞書と意味検索のスクリーン（S2, S2b）がモデルに読ませるべき記録を絞り込み、その残りだけを記録判定（S3）と夜間のセカンドオピニオン（S4）に回します。 最終判断は人（S5）。再現率証明書は、除外によって見逃した可能性のある適格患者数の上限を示します。

使い方

メールで

1 行のコマンドをボックスに送ると、結果があなたのメールボックスに届きます。

宛先: trialbox@your-hospital
件名: FEAS GZQO

ほかに SCREEN、NAV（健保ナビゲーション）、COHORT、記入済み review.xlsx を返信して承認。

管理コンソールで

同じコマンドをボタンで：新規リクエスト、プロトコルのアップロードとレビュー、カスケード実行、各ジョブのメールスレッドと監査証跡。 日本語・中国語・英語で質問を入力すると、コンソールが正確なコマンドを提案し、確認するまで何も実行されません。

動作環境

環境コマンドモデル

任意の Docker ホスト（Linux、macOS、WSL2）deploy/poc.sh決定論的スタブ、またはテスト用 OpenRouter モデル：TB_LLM_MODE=openrouter
クラウド GPU VM（例：GCP の L4 / A100）TB_LLM_MODE=gpu deploy/poc.sh同じ固定版モデルを自社 VM で

POC はボックス一式をテスト用メールサーバーと Web メール付きで起動し、コンソール管理者を作成して、600 人の合成病院データを読み込みます。 詳細：RUNBOOK §8–9（英語）。
