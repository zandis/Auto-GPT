資料不出院，也能找到臨床試驗需要的病人。

TrialBox 是在醫院內運作的收案條件編譯器與病人搜尋設備。它把試驗計畫書、健保給付規定與世代定義， 轉換成可稽核的病人篩選，直接在醫院自己的病歷資料上執行，並透過電子郵件或管理主控台回覆可行性評估。

三個原則

資料不出院

在院內網路的 DGX Spark 或任何 Docker 主機上執行。模型在設備上提供服務，對外連線預設封鎖。 交給試驗委託者的只有經小格抑制的彙總報告。

代理人起草，引擎判定

語言模型只負責從文件擷取條件，以及在結構化資料無法回答時閱讀自由文字病歷。 所有人數都來自由審閱過的規則集產生、並與 CQL 交叉驗證的確定性 SQL。

由人核可

每個編譯完成的規則集由研究協調員在審閱活頁簿中核可，收案資格由試驗主持人決定。 每個請求、模型呼叫與輸出檔都以雜湊寫入只能追加的稽核軌跡。

使用方式

電子郵件

寄一行指令給設備，結果會回到你的信箱。

收件者: trialbox@your-hospital
主旨: FEAS GZQO

另有 SCREEN、NAV（健保申請導航）、COHORT，以及回覆填好的 review.xlsx 進行核可。

管理主控台

同樣的指令變成按鈕：新增請求、上傳與審閱計畫書、執行篩選級聯、每個工作的郵件往來與稽核軌跡。 用中文、日文或英文輸入問題，主控台會建議精確的指令；確認之前不會執行。

部署環境

環境指令模型
NVIDIA DGX Spark（GB10，128 GB）make spark-e2e設備上固定版本的開放權重模型（vLLM）
任何 Docker 主機（Linux、macOS、WSL2）deploy/poc.sh確定性替身模型，或測試用 OpenRouter 模型：TB_LLM_MODE=openrouter
雲端 GPU 虛擬機（例如 GCP 的 L4 / A100）TB_LLM_MODE=gpu deploy/poc.sh同一固定版本模型，在你的虛擬機上

POC 會連同測試郵件伺服器與網頁郵件啟動整套設備、建立主控台管理員，並載入 600 位病人的合成醫院資料。 詳見 RUNBOOK §8–9（英文）。
